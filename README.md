# Оптимизатор продуктовой корзины — MVP

Хранит историю покупок, собирает корзину, тянет цены из магазинов с доставкой, накладывает условия
банковских акций и предлагает разбиение корзины между магазинами с минимальным итогом.

Ключевая метрика — экономия в рублях и процентах относительно baseline (вся корзина в одном
привычном магазине без акций).

## Запуск

```powershell
.\run.ps1 -Seed
```

Откроется http://localhost:8501. Ключ `-Seed` наполняет базу демо-данными (16 эталонов,
3 карты, 5 акций, демонстрационный чек и готовая корзина). Без ключа — просто запуск UI.

Все данные в репозитории вымышленные: и чек, и условия карт, и цены магазинов в
`data/fallback_prices.csv`. Они нужны, чтобы расчёт было на чём показать.

Тесты:

```powershell
.\run.ps1 -Test
```

## Структура

| Путь | Назначение |
|---|---|
| `app/config.py` | Конфигурация из `config.yaml` |
| `app/geo.py` | Адрес: подсказки и перевод в точку на карте. DaData по ключу, иначе OpenStreetMap |
| `app/db.py` | Схема SQLite (раздел 4 спецификации), подключение, сиды магазинов |
| `app/models.py` | Общие типы: Product, Store, Offer, Candidate, PriceSnapshot, BasketLine, Variant |
| `app/repo.py` | Доступ к данным — единственный слой, ходящий в SQLite |
| `app/service.py` | Интеграция: корзина + цены + акции → оптимизатор. Точка входа для UI |
| `app/location.py` | Адрес клиента и подбор точки под каждую сеть: хаб Ленты, ближайший магазин Магнита |
| `app/connectors/` | Коннекторы цен: Магнит, ВкусВилл, Лента, Дикси, заглушка. Кэш 6 ч, троттлинг 1 запрос/с |
| `app/importers/` | Загрузка покупок: чек ОФД (PDF/текст), JSON от ФНС, таблица CSV/XLSX |
| `app/matcher/` | Нормализация названий, поиск кандидатов, подтверждение сопоставлений |
| `app/optimizer/` | Расчёт скидки (раздел 6) и перебор разбиений корзины |
| `app/web/` | Экраны приложения (Flask): Корзина, Результат, Кабинеты, Магазины, Карты и акции |
| `tools/seed.py` | Демо-данные |

## Настройки (`config.yaml`)

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `baseline_store` | `pyaterochka` | Магазин, относительно которого считается экономия |
| `extra_order_penalty_rub` | 150 | Штраф за каждый дополнительный заказ |
| `optimizer.max_stores` | 2 | Глубина перебора разбиений |
| `connectors.rate_limit_rps` | 1.0 | Не чаще одного запроса в секунду на магазин |
| `connectors.cache_ttl_hours` | 6 | Срок жизни кэша цен; протухшие файлы убираются сами |
| `connectors.metro_max_km` | 60 | Дальше этого ближайший центр METRO считается «не вашим» |
| `prices.stale_after_days` | 7 | Старше — цена помечается на «Результате» как несвежая |
| `optimizer.store_extra_rub` | {} | Своя цена времени на сеть (дальний самовывоз): в выбор варианта, не в оплату |
| `geo.dadata_token` | нет | Ключ DaData для подсказок адреса. Без него подсказки берутся из OpenStreetMap — без ключа, но строже к вводу. Можно задать переменной окружения `DADATA_TOKEN` |

## Расчёт (раздел 6 спецификации)

```
subtotal_s = сумма(price * qty) по позициям, отнесённым в магазин s
delivery_s = 0, если subtotal_s >= free_delivery_from, иначе delivery_fee
discount_s = 0, если subtotal_s < min_check_rub, иначе min(subtotal_s * percent / 100, cap_rub - cap_used)
total_s    = subtotal_s + delivery_s - discount_s
total_v    = сумма(total_s) + penalty * (число магазинов в варианте - 1)
```

Скидка нелинейна из-за лимита и минимального чека, поэтому выгода считается на уровне варианта
целиком, а не позиции: бывает выгодно положить товар в магазин, где он дороже, ради минимального чека.

Что ещё учтено (ревизия 26.09.2026):

- **Минимальный заказ магазина — в целевой функции**, а не пометкой после: перебор не выбирает
  разбиение, которое магазин не примет, пока есть допустимое.
- **Цена позиции** (`app/service.py`, `line_price`) — деньги за то, что ляжет в корзину: весовой
  товар сети — цена килограмма × килограммы, фасованный — целые упаковки (вверх, как их положит
  наряд) × цена упаковки. Весовым эталон считается только по доводу (дробное количество, слово
  «весовой»/«кг» в названии, дробные количества в чеках) — не по отсутствию граммовки в названии.
- **Другая фасовка штучного товара** (800 г вместо 1 кг) в оплату идёт ценой полки, а в выбор
  варианта — с поправкой к весу эталона (`Variant.pack_extra`).
- **Экономия** считается по тем позициям, что в варианте есть: недостающий товар — не выгода.
- **Несвежие и справочные цены** (старше `prices.stale_after_days` или из `fallback_prices.csv`)
  идут в расчёт, но называются на «Результате» поимённо.
- Штучный товар в корзине — целыми штуками.

## Ограничения MVP

- Внутренние API магазинов не документированы; при недоступности коннектор падает на
  `data/fallback_prices.csv`, расчёт не блокируется.
- Цены на сайте и в офлайн-магазине расходятся на 5–15 % — продукт показывает ориентировочную
  стоимость, не прайс-лист.
- Персональные банковские офферы вводятся вручную или загружаются CSV.
- В расчёт идут только подтверждённые сопоставления.
