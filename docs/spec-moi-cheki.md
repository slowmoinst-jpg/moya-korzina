# Экран «Мои чеки»: вход в сервис ФНС внутри приложения

Как это должно выглядеть для человека, почему этого нельзя сделать в вебе и что
нужно, чтобы сделать в приложении.

> **Что изменилось 15.09.2026.** Половина этой спецификации уже работает в вебе — не
> так, как здесь написано, но с тем же итогом. Закладка «Забрать чеки»
> (`docs/grab.src.js`) запускается НА странице кабинета и обходит его целиком: список
> чеков постранично (`POST /api/v1/receipt`), затем позиции по каждому
> (`POST /api/v1/receipt/fiscal_data`) — теми же запросами, какие кабинет делает сам.
> Ключ доступа остаётся в браузере, через наш сервер не идёт ничего.
>
> Проверено на поддельном кабинете (`fake_lkdr.py` в песочнице сессии): 250 чеков,
> 6 запросов списка, 250 запросов за позициями, ни одного без пропуска, повторный
> заход не тянет ничего. На живом кабинете ФНС не проверялось — нет учётной записи.
>
> Что осталось ручным: нажать закладку и принести файл в приложение. Всё, что ниже,
> остаётся в силе для мобильного приложения — там исчезнет и это.

## Что видит человек

1. В приложении раздел **«Мои чеки»**. Внутри — кнопка «Подключить сервис ФНС».
2. Открывается **окно с сайтом ФНС** прямо в приложении. Не переход в браузер,
   не «скопируйте ссылку» — окно внутри.
3. Человек **сам** вводит номер телефона и код из СМС. Ввод идёт в страницу
   налоговой; приложение к полям не прикасается.
4. Он видит свои чеки — в нашем же окне, как если бы открыл сайт.
5. Снизу поверх окна — **наша полоса с кнопкой «Загрузить эти чеки»**.
6. Нажал — позиции разобрались и легли в историю покупок. Экран закрылся.

Никакого копирования, никаких закладок, никаких переходов между приложениями.
Ровно то, о чём шла речь.

## Почему этого нельзя сделать в вебе

Проверено запросом, а не по памяти. В страницу нашего приложения встраивается
`iframe` с `lkdr.nalog.ru`, и делается попытка прочитать его:

```
iframe загрузился ............. да
frame.contentDocument ......... null
frame.contentWindow.location .. SecurityError
frame.contentDocument.cookie .. TypeError
```

Сайт ФНС встраивание не запрещает — заголовков `X-Frame-Options` и
`Content-Security-Policy: frame-ancestors` у него нет, и в живом приложении окно
с кабинетом открывается: форма входа по номеру телефона видна на нашей странице.
**Пункты 1–4 в вебе работают.**

А вот содержимое чужого источника недоступно странице по правилу браузера
(same-origin policy). Это не настройка и не недоработка: обойти нельзя никаким
кодом на нашей стороне. Значит **пункты 5–6 в вебе невозможны** — кнопка
«Загрузить» была бы обманом, и вместо неё человек копирует чек прямо из
встроенного окна.

### Чего делать нельзя даже при желании

Существует способ обойти правило: пропускать сайт ФНС через свой сервер, подменяя
адреса так, чтобы для браузера он стал «своим». Тогда читать можно всё. Но тогда
через наш сервер пойдут и номер телефона, и код из СМС, и сессия к налоговой.
Это ровно та граница, за которую мы не идём: держать чужой вход к госсервису у
себя нельзя ни технически, ни юридически, ни перед человеком.

## Как это делается в приложении

В мобильном приложении окно с сайтом — **наш собственный WebView**. Правило про
разные источники к нему не относится, потому что читает не страница, а само
приложение, которому этот WebView принадлежит.

### Android, по шагам

```kotlin
// 1. WebView, в котором человек входит сам
webView.settings.javaScriptEnabled = true
webView.settings.domStorageEnabled = true
webView.loadUrl("https://lkdr.nalog.ru/")

// 2. Мост, по которому страница отдаёт текст приложению
class Bridge(private val onText: (String) -> Unit) {
    @JavascriptInterface
    fun take(text: String) = onText(text)
}
webView.addJavascriptInterface(Bridge(::onReceiptsTaken), "MoyaKorzina")

// 3. Кнопка «Загрузить эти чеки» — наша, в интерфейсе приложения, не на странице
fun onGrabClicked() {
    webView.evaluateJavascript(EXTRACT_JS, null)   // скрипт сам позовёт MoyaKorzina.take(...)
}
```

`EXTRACT_JS` — это уже написанный и проверенный код извлечения текста из
[docs/grab.src.js](grab.src.js): выбор содержательной части страницы, обход дерева
с расстановкой переводов строк, чистка от навигации, приоритет выделенного мышью.
Работа над букмарклетом не пропадает — его ядро переезжает сюда дословно, только
вместо буфера обмена вызывается мост.

Дальше текст уходит в тот же разбор, что уже работает: `app/importers/orders.py`.
Ни строчки нового кода для понимания чеков не потребуется.

На iOS то же самое: `WKWebView`, `evaluateJavaScript`, `WKScriptMessageHandler`
вместо `@JavascriptInterface`.

### Границы, которые задаются в коде, а не на словах

| Правило | Как обеспечивается |
|---|---|
| Приложение не видит код из СМС | ввод идёт в страницу; обработчиков ввода не ставим, `evaluateJavascript` зовём только по нажатию кнопки |
| Сессия не сохраняется | при закрытии экрана `CookieManager.removeAllCookies()` и `WebStorage.deleteAllData()` |
| Фоновых запросов нет | никакого таймера и никакой работы, пока человек не нажал |
| Берём то, что видно | читаем отрисованную страницу, внутренние методы сервиса не вызываем |

Последняя строка — та самая граница между «ускоренной копипастой» и «интеграцией,
взятой без спроса». Читать страницу, которую человек перед собой видит, по его
нажатию — одно. Дёргать приватное API его сессией — другое, и для этого
существует партнёрская программа.

## Что нужно, чтобы это появилось

Мобильная оболочка. И тут хорошая новость: переписывать приложение не надо.

**Тонкая оболочка на Android** — это два WebView и немного связующего кода:

- WebView №1 показывает наш интерфейс (сегодня Streamlit, завтра что угодно);
- WebView №2 — экран «Мои чеки» с сайтом ФНС и нашей кнопкой;
- мост между вторым и приложением;
- отправка снятого текста в наш разбор.

Порядок величины — несколько сотен строк Kotlin, не переписывание продукта.
И это же оболочка, которая потом нужна для публикации в Google Play и RuStore,
для сканера штрихкодов камерой и для чтения QR с чека. То есть работа не ради
одной функции.

## Честная оговорка про сроки и риски

**Собрать и проверить APK я отсюда не могу** — нет Android SDK и устройства.
Написать оболочку могу, проверить её работу — нет. Первую сборку и первый запуск
придётся делать вам или тому, у кого настроено окружение.

**Риски, которые надо знать заранее:**

- Пользовательское соглашение ФНС автоматизированный доступ, скорее всего, не
  разрешает. «По нажатию, то, что видно на экране» — серая зона, защитимая, но
  серая. Партнёрство её закрывает, этот путь — нет.
- Google Play и RuStore смотрят на связку «WebView плюс вход в госсервис»
  пристально. В описании приложения придётся объяснять, что происходит, и лучше
  объяснять честно.
- Вёрстка кабинета ФНС изменится — разбор сломается. Это чинится правкой
  извлечения, но чинить придётся.

**И главное, что этот путь не даёт.** Человек загружает то, что сам открыл, по
одной странице. Партнёрство даёт всю историю разом и потом само, без его участия.
Так что экран «Мои чеки» — мост на время оформления, а не замена ему.

## Что до тех пор

Работает и не требует ничего: вставка текста на экране «История». На телефоне
чек распознаётся камерой — «Живой текст» на iPhone, Google Объектив на Android —
и вставляется как есть. Букмарклет из [grab.html](grab.html) полезен на
компьютере, но для телефона он и правда не годится.
