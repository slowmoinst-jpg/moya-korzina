# Откуда сети отдают корзину и выгоду — разведка 17.09.2026

Снято в **браузере владельца**, где он вошёл в свои кабинеты Пятёрочки, Магнита и
Самоката. Это его собственные данные и его собственные входы; ничего, кроме
структуры ответов, отсюда не выносится — ни токенов, ни номеров карт.

Способ один и тот же и он честный: открыть страницу, спросить у браузера
`performance.getEntriesByType('resource')` — то есть список адресов, по которым
сходила **сама страница**, — и посмотреть, что лежит в её `localStorage`. Никаких
перехватов, подмен и разбора чужого протокола: сеть сама называет свои адреса
каждому, кто её открыл.

## Коротко: три сети устроены по-разному, и это главное

| | Пятёрочка | Магнит | Самокат |
|---|---|---|---|
| Как отдаёт страницу | приложение на JS (Next.js) | **отрисовка на сервере** | приложение на JS (Next.js) |
| Наш сервер видит её обычным запросом | нет | **да** | нет |
| Где корзина | `localStorage.cart-store` + API | в разметке страницы | API `v2/carts/get` |
| Чем доказывается вход | `server_token` (кука и localStorage) | кука `mg_at` | Bearer из `/api/auth/session` |
| Личные акции | `offerhub-integration/v3/offers/all` | в разметке профиля | `promo/v2/<витрина>/personal-section` |

Отсюда вывод, который стоит держать в голове: **одной дороги на шесть сетей не
будет**. У Магнита читается страница, у Самоката — опрятный JSON, у Пятёрочки —
JSON, но с подписью запросов.

## Самокат — самый опрятный путь

`https://samokat.ru/api/auth/session` отвечает **по одним кукам**, без заголовков:

```
{ accessToken, accessTokenExpires, refreshToken, sessionToken, expires }
```

Замер: `expires` — через год. То есть, получив куки один раз, можно долго брать
свежий `accessToken` и не просить человека входить заново.

Дальше всё под `Authorization: Bearer <accessToken>` на `api-web.samokat.ru`
(без него — 401 `EMPTY_HEADER_AUTHORIZATION`):

```
GET  /users/profile                               профиль
GET  /v2/carts/get                                КОРЗИНА
GET  /promo/v2/<витрина>/personal-section         ЛИЧНЫЕ АКЦИИ
GET  /promo/<витрина>/media-slider                баннеры акций
GET  /v2/showcases/<витрина>/main                 главная витрины
GET  /v2/showcases/<витрина>/categories/list      разделы
GET  /v2/showcases/<витрина>/categories/discount/<id>   раздел скидок
GET  /aggregation/products                        товары
GET  /payments/types, /orders/statuses/tracking, /refunds/active
```

«Витрина» — идентификатор точки по адресу человека (в замере
`35ad943e-c956-4a31-9333-f5e02cc5c2b0`). Он и есть привязка цен к адресу.

Ещё в `localStorage` лежит `X-Device-Uid` — идентификатор устройства; сеть
привязывает к нему сеанс.

## Пятёрочка — JSON, но с подписью

Адреса, по которым ходит сама страница:

```
GET  https://5ka.ru/api/authV2/session                       сессия
GET  https://5d.5ka.ru/x5m/api/offerhub-integration/public/v3/offers/all   ЛИЧНЫЕ АКЦИИ
GET  https://x5m.x5.ru/common/api/points/public/v1/balance   баллы
GET  https://x5m.x5.ru/common/api/cards/public/v1/card-list  карты X5
GET  https://5d.5ka.ru/api/orders/v3/orders/                 заказы
GET  https://5d.5ka.ru/api/orders/v10/orders/<uuid>/         ЗАКАЗ (он же корзина)
GET  https://5d.5ka.ru/api/orders/v1/orders/stores/          магазины
GET  https://5ka.ru/api/maps/geocode/                        адрес → точка
```

Одних кук им мало: `points/balance` отвечает `403 RBAC: access denied`, а
`offers/all` не пускает вовсе. Вход доказывается `server_token` (он лежит и кукой,
и в `localStorage`, 312 знаков).

**И вот чего трогать не станем.** В `localStorage` рядом лежат `privateKey` (1268),
`publicKey` (324) и `salt` (128) — то есть страница **подписывает свои запросы**.
Воспроизвести подпись на нашем сервере значило бы выдать его за приложение сети.
Это ровно та граница, которая записана в шапке `app/shopbrowser/__init__.py`, и она
не двигается. Значит у Пятёрочки наш путь — не подделывать её запросы, а читать то,
что лежит открыто.

А лежит открыто немало. **Корзина Пятёрочки живёт в `localStorage.cart-store`** (в
замере 6 КБ) и содержит всё, что нужно расчёту:

```
order.basket:  items[], items_count, weight, basket_status
               total_sum "334.99"      до скидок
               total_discount "134.00" выгода
               final_sum "249.99"      к оплате
               delivery_cost "0.00", price_promocode "0.00"
               full_summary { subtotal, loyalty, additional, total }
               retailer_id "D", sap_code — магазин
order.address: city, street, house, lat, lon, region
order.user:    card — номер карты X5
```

Выгода — там же: `LoyaltyStore.loyaltyData` (`cardNo`, `points`, `rub`, `lifetime`,
`cardStatus`), `loyalty-balance-cache` (`{points, rubles}`), `loyalty-cards-cache`
(карты `X5VC`).

Личные акции видны и глазами на `/special-offers/`: в замере это «−15 % на заказ от
1600 ₽» с промокодом, «+10 % баллов за макаронные изделия на 5 дней», товарные
предложения. Промокод — обычная строка на странице.

## Магнит — всё в разметке, и это удобно

Ни одного запроса `fetch`/`xhr` при открытии: страница приходит собранной. Наш
сервер её получает (замер 17.09.2026: 200 и 1,2 МБ), значит браузер на сервере под
сохранённым входом читает её так же, как читал бы человек.

Вход — кука `mg_at` (замерена живьём на телефоне 17.09.2026, 648 знаков, и она
**не** HttpOnly). Рядом живут `mg_udi`, `shopCode`, `x_shop_type`, `nmg_dt` —
последние три задают магазин и способ получения, из-за чего у Магнита цена зависит
от кук, а не от адреса в строке (см. шапку `app/connectors/magnit.py`).

Выгода лежит в профиле разделами: «Личные данные», **«Категории с кешбэком»**,
«Карта Магнит Плюс», «Бонусы от партнёров», «Акции». Всё это — обычный текст
страницы.

Шлюз `magnit.ru/webgate` (v1/v2) отдаёт товары и магазины и уже используется в
`app/connectors/magnit.py`. Маршруты входа в его коде не написаны словами — они
собираются на лету (`${l}/webgate`), поэтому из кода сайта их не вычитать.

## Что из этого следует для приложения

1. **Общего клиента на шесть сетей писать нельзя** — у каждой своя дорога.
2. **Вход везде проходит человек.** Мы берём только то, что сеть выдала после него.
3. **У Самоката путь прямой:** куки → `accessToken` → корзина и личные акции JSON.
4. **У Пятёрочки берём открытое:** `cart-store` и `LoyaltyStore` из `localStorage`
   той же страницы, где человек вошёл. Подпись запросов не трогаем.
5. **У Магнита читаем страницу** — тем браузером на сервере, который уже написан.
6. Ленту, ВкусВилл и Дикси так же не разведывали: владелец в них не вошёл.

## Где проходит граница

Разведка смотрела только на то, что сеть сама показывает вошедшему человеку в его
собственном браузере. Ни одного чужого кабинета, ни одной попытки обойти проверку,
ни одной подделанной подписи. Всё, что здесь записано, человек может увидеть сам,
открыв «Инструменты разработчика» на своей же странице.

# Продолжение 19.09.2026: где корзина открывается нашему приложению

Поручение владельца: «найти способ авторизации и возможности формировать корзины
из приложения нашего после расчёта в нужных нам магазинах». Замер сделан **с
боевого сервера**, одним запросом в четыре секунды, слоем
`app/catalog/crawlers.http_get` — тем же, которым ходят сборщики каталога.
Инструмент замера оставлен в репозитории: `tools/probe_cart.py`.

Проверялись четыре сети, у которых **каталог уже есть, а передачи корзины не
было**: METRO, Перекрёсток, Впрок, Монетка. Из них METRO — не просто одна из
четырёх: она **магазин расчёта** (`app/db.SEED_STORES`), то есть оптимизатор мог
послать туда человека, а передать ему было нечего, кроме списка.

## METRO — сеть сама описала, как наполнять её корзину

Это единственный такой случай за всю разведку. Спецификация выложена публично и
отдаётся без ключа: `https://api.metro-cc.ru/docs`, OpenAPI 3.0, 141 КБ.

```
GET    /{api_token}/{store_id}/eshop/basket/?user_hash=…     что сейчас в корзине
POST   …/eshop/basket/?user_hash=…   {"articles":[{"article":N,"count":K}]}
PUT    …/eshop/basket/?user_hash=…   {"article":N,"count":K}
DELETE …/eshop/basket/?user_hash=…&eshop_products_id[][eshop_product_id]=…
```

### Что измерено живьём

| запрос | ответ |
|---|---|
| `GET /api/v1/16/eshop/basket/` без всего | 200, 424 байта, корзина пустая, `user_hash=5502aed9…`, `minimal_cost: 1500` |
| куки после него | `metro_user_id` = **тот же хеш**, плюс `metro_api_session` |
| второй `GET` той же сессией | хеш **тот же** |
| `GET` с `user_hash` параметром | хеш принят, отдана та же корзина |
| `GET https://online.metro-cc.ru/` | 200, 1,99 МБ — витрина открывается нашему серверу сразу |
| `GET /api/v1/tradecenters` | 200, 64 КБ, все точки сети |

### Тот ли это хеш, что у человека — проверено настоящим браузером

Обычным запросом витрина `online.metro-cc.ru` куку `metro_user_id` не ставит: её
ставит скрипт, сходивший к интерфейсу. По одному этому ответу можно было решить,
что у витрины хеш свой, и весь канал оказался бы бесполезным. Замер окном
магазина (`app/shopbrowser`, серверный Chromium, 19.09.2026):

```
окно открыло https://online.metro-cc.ru/  → проверки нет, guarded: False
сеть поставила 48 кук, среди них          metro_user_id = e3b63cd2e222822c002cd29a0603cf70
тот же хеш спрошен у интерфейса           → принят, отдана та же корзина
```

**Главный вывод.** `user_hash` — это и есть кука `metro_user_id`, и корзина
находится по нему. Хеш, который сеть выдала ОКНУ ЧЕЛОВЕКА, интерфейс признаёт
своим. Значит наполняем **ту самую корзину, которую человек видит у себя**: его
хеш лежит в его же сохранённом входе (`app/shopbrowser/store.py`). Своего,
серверного хеша мы не подставляем — наполненная им корзина осталась бы нашей и
человеку бесполезной.

**Вход для этого не обязателен:** корзину METRO заводит и гостю. Вход добавляет
цены по карте клиента и историю, но чтобы позиции легли, довольно открытого окна.

### Запись проверена, и она НЕ проходит без именного токена

Владелец разрешил проверить запись живьём — проверили, и вывод оказался обратным
тому, на который было похоже.

```
POST /api/v1/10/eshop/basket/?user_hash=…   {"articles":[{"article":117189,"count":1}]}
     store_id=10 — настоящий, снят из перечня самой сети (у METRO id и store_id РАЗНЫЕ поля)
     артикул 117189 — сахар aro, остаток 7463, в наличии
     хеш — тот, что сеть выдала НАШЕМУ ЖЕ окну
→ 400 {"success":false,"data":[],"errors":"Basket not found"}

POST …/eshop/basket/set-delivery-type?pick_up=1 без токена → 404
```

Метода «создать корзину» в спецификации **нет вовсе** — проверено по всему
разделу paths. Оставалась догадка, что корзину заводит сама витрина, когда
человек кладёт первый товар. Проверили и её: серверный Chromium открыл карточку
и нажал «в корзину» тем же кодом, которым идёт передача.

```
нажали «в корзину»                  → легло, и это не ложный успех:
                                      рекламный пиксель витрины ушёл с
                                      param1=$$product_add_to_cart$$
                                      param4=$$117189$$ param5=$$66.9$$
хеш окна                            → не изменился
корзина по этому хешу (точка 10)    → позиций 0, eshop_basket_id=None
```

То есть витрина товар приняла, а в корзине, которую отдаёт бестокенный путь, его
нет. **Почему — видно по тому, чем живёт сама витрина.** Список адресов, по
которым сходила её страница (`performance.getEntriesByType('resource')`, тот же
способ, что в разведке 17.09.2026):

```
https://api.metro-cc.ru/api/v1/{ТОКЕН}/10/disclaimer
https://api.metro-cc.ru/auth/api/v1/refresh
```

Настоящий маршрут — **тот, что описан в спецификации, с сегментом токена**.
Бестокенный путь отдаёт чтение и не отдаёт запись; прежний вывод «похоже на
недосмотр маршрутизации» подтвердился с неприятной стороны — недосмотр кончается
там, где начинается запись.

**Чужой токен мы не берём.** Токен витрины виден в её собственных запросах, и
соблазн подставить его очевиден. Не подставляем: он выдан не нам. Именной токен
получают через форму METRO для бизнеса, тема «Запросы на сотрудничество».

**Что из этого следует для кода.** `metro_cart.writable()` спрашивает токен, и
без него `fill` отказывается **до запроса**, называя настройку
`connectors.metro_api_token`; `store_accounts` не обещает METRO умения `CART`, а
`handover` держит её на ступени карточек. Появится токен — канал включится сам,
без правок: вся дорога до записи проверена.

## Впрок — витрина открыта, интерфейс не найден

`GET https://www.vprok.ru/` — **200, 456 КБ**, настоящая разметка с ценами и
кнопками «Купить». То есть наш сервер эта сеть пускает, и окно магазина
(`app/shopbrowser`) у неё работать будет.

А вот **программного канала пока нет**, и здесь стоит запомнить методическую
ошибку, которую сторож поймал в тот же час:

```
GET /web/api/v1/cart              → 401
GET /web/api/v1/user/current      → 401
GET /web/api/v1/net-takogo-metoda → 401      ← выдуманный адрес
```

Первые два 401 читались как «маршрут есть, нужен вход». Третий показал, что
**401 у этой сети общий на всю ветку** и о существовании метода не говорит
ничего. Вывод был бы ложным. Правило: гадая пути, всегда проверяй выдуманным.

Настоящие адреса лежат не в разметке (в HTML нет ни одного `/api/`), а в
скриптах: в состоянии страницы видно `"cart":{"status":"initial","batchItems":[],
"positions":[]}` — слово `batchItems` намекает, что пачку класть сеть умеет.
Чтобы узнать адрес, нужно открыть витрину настоящим браузером и посмотреть, куда
она сходит по нажатию «Купить». Это следующий шаг, а не сделанный.

## Перекрёсток — до сети дело не доходит

`GET https://www.perekrestok.ru/` — 200, но **1776 байт**: заглушка антибота с
`<noscript><meta http-equiv="refresh" content="0; url=/exhkqyad">`. Все запросы к
`/api/customer/1.4/*` — 403 после повторов с паузами.

Это тот же класс, что Лента и Дикси: проверка выполняется в браузере, и обычный
запрос до сети не доходит. Значит дорога к Перекрёстку — **окно магазина**, а не
запрос с сервера. Не сделано.

## Монетка — закрылась целиком

19.09.2026 утром её карточки отвечали 401, а карта сайта отдавалась. К вечеру
того же дня **401 отвечает уже и главная страница**, и раздел входа. Каталог
Монетки у нас есть (7 576 товаров из карты сайта), цен и корзины нет и пока не
предвидится.

## Что из этого сделано

| сеть | вход | корзина сегодня | что её включит |
|---|---|---|---|
| METRO | окно магазина работает | ссылки на карточки | **именной токен сети** — канал написан и проверен до самой записи |
| Впрок | окно магазина заработает | — | найти адрес, которым витрина кладёт товар |
| Перекрёсток | только окно магазина | — | сервер до сети не доходит |
| Монетка | — | — | сеть отвечает 401 на всё |

Итог поручения одной фразой: **у METRO найден и построен канал сильнее всех, что
у нас есть, и он упирается ровно в одну недостающую вещь — именной токен**, а не
в незнание протокола. Всё остальное измерено и работает: окно открывается без
проверки, хеш корзины совпадает с хешем человека, чтение проходит, форма запроса
записи взята из спецификации сети.

# Автоматика наряда: что измерено 19.09.2026 настоящим браузером с сервера

Поручение владельца: «продолжай решать технические аспекты и автоматизировать
формирование корзин, моё участие в самом конце». Инструмент замера оставлен в
репозитории: `tools/cartcheck.py`.

## Куда наш сервер вообще доходит

| сеть | что показывает нашему Chromium |
|---|---|
| Магнит | витрина, 136 ссылок, кнопки «В корзину» — **работает** |
| ВкусВилл | витрина, 200 ссылок, ссылка `/cart/` — **работает** |
| METRO | витрина, 143 ссылки, счётчик «0 Корзина» — **работает** |
| Лента | `403 Error Forbidden. Доступ к сайту lenta.com запрещен. IP: <адрес сервера>` |
| Дикси | `Не удалось загрузить сайт. Возможно, у вас включён ВПН` |
| Пятёрочка, Самокат | та же блокировка по адресу |

**Это опровергает то, что было написано в шапке `app/shopbrowser/__init__.py`**:
«четыре сети встречают нас проверкой, потому что мы пришли без браузера, а
настоящий браузер выполнит её сам». Настоящий браузер выполнил — и получил отказ
по адресу запроса. До проверки дело не доходит вовсе.

Следствие в коде: `signals.guard_kind` различает теперь три случая вместо двух —
`check` (капчу проходят), `blocked` (страница глухая), `forbidden` (сеть назвала
наш адрес). Человеку в последнем случае говорят правду: «Обновить» не поможет,
эту сеть надо открывать со своего телефона.

## Три способа, которыми наряд врал, и все три закрыты

### 1. Жал не ту кнопку

Наряд брал **первую подходящую** кнопку в порядке разметки. Карточка Магнита,
4017 точек высоты, 28 подходящих кнопок:

```
y=3      «В корзину»            ← плавающая панель, её и жали
y=356    заголовок товара (h1)
y=523    «Добавить в корзину»   ← кнопка ЭТОГО товара
y=1159   «В корзину» ×20        ← карусель «с этим покупают»
```

Панель перерисовывалась, нажатие падало, и человек читал «карточка перерисовалась
под пальцем» при живой рабочей кнопке пятьюстами точками ниже. На METRO та же
картина: h1 на 265, кнопка товара на 457, а первой в разметке идёт невидимая.

Правило, которое обе сети подтверждают и которое теперь в коде: **кнопка товара —
первая видимая ниже заголовка**. После правки нажатие на Магните проходит.

### 2. Верил нажатию, а не корзине

Нажатие «прошло» — значит легло. На METRO это чуть не стоило неверного вывода в
обе стороны: витрина товар приняла (её рекламный пиксель ушёл с
`product_add_to_cart`), а счётчик корзины как показывал ноль, так и остался.

Теперь после передачи читается **счётчик самой сети** (`cart.in_cart`). Ноль при
непустом наряде — громкое «ВНИМАНИЕ», а «счётчика не видно» и «ноль» — разные
ответы: у Магнита пустая корзина подписана без числа вовсе, и прочитать это как
ноль значило бы объявить провалившейся удавшуюся передачу.

### 3. Не замечал, что сеть ждёт выбранного магазина

Третья причина пустой корзины, и самая незаметная. Пока магазин не выбран, Магнит
держит поверх страницы окно «Выберите магазин или адрес», нажать «в корзину»
**даёт**, а в корзину не кладёт ничего; `/cart`, `/basket` и `/cart/` показывают
то же окно вместо корзины. Наряд прошёл бы шестнадцать карточек и отчитался
«легло 16».

Проверяется теперь **до первой карточки** (`signals.needs_store`). Выбрать точку
за человека мы не станем — цена, наличие и доставка у сетей свои в каждой, это
решение про его деньги, — но и вслепую не отправляем: сообщение называет ту точку,
по которой считало приложение (`cart._which_point`). Иначе он выберет соседнюю, и
расчёт, который он видел, окажется не про его покупку — ровно как уже случилось со
ссылкой Ленты.

Кука `shopCode` магазин не задаёт: проверено, окно остаётся.

## Что осталось и почему это упирается во вход

Дальше замер упирается в одно: **наряд по-настоящему проверяется только сессией
человека**. Гостю Магнит не даёт корзины без выбранной точки, ВкусВилл на `/cart/`
пишет «Для оформления заказа необходимо авторизоваться», METRO гостю корзину
заводит, но кладёт только по токену. Это не догадка, а то, что видно на страницах.

Поэтому участие владельца сведено к одному разу и к одному месту: войти в кабинет
сети в окне магазина и выбрать свою точку. Всё, что после этого, приложение делает
само и проверяет само.

# Развесное у Ленты: ошибка в деньгах, которую чинили дважды

Найдено 19.09.2026 при перечитывании схемы инструментов Ленты — той самой, по
которой уже год строится ссылка-корзина.

## Что было сломано

`lenta.cart_link` округляла любое количество вверх до целого и слала его как
`quantity`. Для развесного товара «1» — это **одна фасовка**, а фасовка у каждого
товара своя. То есть:

```
0,7 кг сыра ЛАМБЕР (фасовка 500 г)  → quantity 1 → человек получал 500 г
2,0 кг картофеля  (фасовка 1000 г)  → quantity 1 → человек получал 1 кг
```

Ошибка молчаливая и в деньгах: корзина выглядит собранной, а сумма не сходится с
расчётом, и понять почему нельзя.

## Первая правка была НЕВЕРНОЙ, и это стоит записать

Описание `storefront_cart_link_create` у самой Ленты говорит:

> Для развесных (isWeight в storefront_product_details) quantity — целые граммы,
> кратные saleLimit.stepGrams.

По этому описанию и была написана первая правка: переводить килограммы в граммы.
Спасла проверка на настоящих товарах (точка «Москва, Ходынский бульвар 4»):

| товар | weightGrams | saleLimit |
|---|---|---|
| Картофель, весовой | 1000 | min 1, max 15, step 1 |
| Картофель красный, весовой | 1000 | min 1, max 127, step 1 |
| Сыр ЛАМБЕР полшара, весовой | 500 | min 1, max 10, step 1 |
| Сыр NATURA Сливочный, весовой | 300 | min 1, max 14, step 1 |
| Сыр СВАЛЯ Дваро, весовой | 300 | min 1, max 5, step 1 |
| Сыр УГЛЕЧЕ ПОЛЕ, весовой | 300 | min 1, max 1, step 1 |

Если бы `quantity` был в граммах, `max 15` означало бы «не больше пятнадцати
граммов картофеля». Бессмыслица. В фасовках всё сходится: пятнадцать раз по
килограмму. У всех семи проверенных товаров `stepGrams = 1`, и цена согласуется:
`price = pricePerKg × weightGrams / 1000`.

**Вывод: `quantity` — число фасовок по `weightGrams`, поля названы неудачно.**
Первая правка отправила бы 0,7 кг картофеля как **семьсот фасовок**, то есть
сделала бы хуже, чем было.

Правило, которое из этого следует и которое стоит помнить за пределами Ленты:
**когда описание и данные противоречат, верить данным**. Описание не проверить, а
данные сходятся на каждом товаре и согласуются с ценой.

## Как сделано

`_weight_rules(sku, location)` спрашивает у сети `isWeight`, `weightGrams` и
границы, `cart_link` считает `ceil(кг × 1000 / weightGrams)` и не переходит
потолок. Округление ВВЕРХ — то же правило, что в наряде: недодать человеку хуже,
чем положить чуть больше. Точка приезжает из `app/service.cart_link`
(`location.for_store`), потому что карточку Лента отдаёт только по точке; без
точки считается по-старому, одной фасовкой на килограмм.

Проверено живьём с боевого сервера: ссылка создана, сыр 0,7 кг ушёл как 2 фасовки
по 500 г, картофель 2 кг — как 2 фасовки по 1000 г, штучное — как 2 штуки.

`isWeight` спрашиваем у сети, а не выводим из названия: наш `_unit` ищет слово
«весов» в названии — это догадка, и сеть её иногда опровергает.

## Корзина Магнита: точка расчёта, окно выбора и проверка нажатия (20.09.2026)

Замеры живым Chromium — с рабочей машины и с боевого сервера.
Всё ниже проверено, а не выведено из чужой документации.

### Корзина наполнялась в ЧУЖОЙ точке

Чистое окно Магнита приходит с уже поставленной кукой `shopCode=%22992301%22` —
это магазин, который витрина выбрала себе сама. То же молоко Простоквашино
2,5 % 930 мл стоит в нём **84,99 ₽**, а расчёт показывал человеку **89,99 ₽** по
его точке. Корзина собиралась настоящая, сумма в ней — не та, которую человек
видел, и заметить это он мог только на кассе.

Точка переносится тремя куками — `shopCode`, `x_shop_type`, `nmg_dt`. Что ими
выбирается магазин, было замерено 12.09.2026 на ШЛЮЗЕ (`magnit.ru/webgate`);
20.09.2026 это подтверждено на самой ВИТРИНЕ: одна карточка, два магазина, две
цены. Сквозная сверка через боевой код: расчёт 89,99 ₽ и витрина 89,99 ₽ в точке
264856 — сошлось.

Форма значения — её собственная: код в кавычках, закодированных процентами
(`%22264856%22`). Сырые кавычки витрина принимает и переписывает в свою форму.
Сделано в `app/shopbrowser/point.py`.

### Не во всякий магазин корзину собрать можно

Одна и та же карточка, разные форматы точки:

| формат | код | город | что на карточке |
|---|---|---|---|
| ME | 992301 | Москва | 84,99 ₽, «В корзину» |
| MM | 264856 | Москва | 89,99 ₽, «В корзину» |
| GM | 995402 | Новосибирск | 84,99 ₽, «В корзину» |
| DARKSTORE | 730884 | Москва | 89 ₽, «Нет в наличии» |
| **MM_MINI** | 628425 | Москва | **«Не удалось загрузить»** |
| **MM_MINI** | 080870 | Новосибирск | **«Не удалось загрузить»** |

Два разных MM_MINI в двух городах дали одно и то же, а нехватка товара
(даркстор) выглядит совсем иначе — страница открывается и честно говорит «Нет
в наличии». Значит дело не в товаре и не в отдельном магазине: у «Магнита у дома
мини» интернет-витрины нет вовсе, заказать из него нельзя никак. Наряд в такую
точку не идёт и называет ближайшую, из которой можно (`point.trouble`).

Слова «сайт» в этой странице нет, поэтому прежний сторож `BLOCKED` её не ловил:
разбор считал её обычной витриной, кнопки на ней не находил и объявлял человеку
«похоже, вёрстку переделали». Добавлен отдельный признак `signals.NO_SHOWCASE`.

### Окно выбора магазина стоит только перед нашим сервером

С рабочей машины окна «Выберите магазин или адрес» на карточке нет вовсе. Нашему
серверу Магнит показывает его **даже при верной куке точки** — то есть упор был
не в невыбранный магазин, а в адрес, с которого мы стучимся.

У окна две кнопки. После «Не сейчас» окно уходит, кука `shopCode` остаётся
нашей, кнопки «В корзину» возвращаются, шапка пишет «Доставка • Экспресс». Это
ОТКАЗ выбирать, а не выбор, и нажимать его можно только там, где точка расчёта
уже передана: без неё за окном стоял бы магазин витрины.

### Нажатие может не значить ничего, и это видно по запросам

Наряд нашёл правильную кнопку («Добавить в корзину», не плавающую панель и не
карусель), нажал её и отчитался «легло». Подсмотр изнутри страницы — обёртка над
`fetch` и `XMLHttpRequest.open`, ставится через `add_init_script`, — показал всё,
что уходит после нажатия:

    mc.yandex.ru/clmap/56708149          200    счётчик посещений
    mc.yandex.ru/clmap/108712515         200    счётчик посещений
    w-12840.fp.kaspersky-labs.com        200    чужой счётчик, ×2
    mc.yandex.ru/watch/56708149/1        200    цель «…buyBox_toCart_click», ×2
    magnit.ru/magnit-id/anti-fraud/api/fl 200   антифрод самого Магнита, ×2

К корзине — **ни одного обращения**. И так с закрытым окном выбора магазина, и
без него, и с боевого сервера, и с рабочей машины. Карточка после перезагрузки
неизменно снова предлагает «Добавить в корзину».

ПЕРВАЯ ВЕРСИЯ ЭТОЙ ПРОВЕРКИ СЛОМАЛАСЬ РОВНО ЗДЕСЬ, И ЭТО ГЛАВНЫЙ УРОК РАЗДЕЛА.
Она отбирала свои запросы по слову в адресе — и «единственным запросом к
корзине» посчитала пиксель Метрики:

    POST mc.yandex.ru/watch/56708149/1
         ?page-url=goal://magnit.ru/product_productPage_buyBox_toCart_click

Слово `cart` в нём есть (внутри `toCart_click`), имя `magnit.ru` тоже есть —
в параметрах, — ответ 200, и летит он при КАЖДОМ нажатии. То есть ноль не
наступал никогда: сторож, поставленный ловить молчание сети, считал чужой
счётчик и не защищал ни от чего, выглядя при этом рабочим. Полтора часа замеров
после этого ушло на вывод «запрос всё-таки уходит», который был неверен.

Отсюда два правила, оба воплощены в `cart.own_cart_calls`:

* хозяин адреса сверяется ЦЕЛИКОМ, а слова ищутся только в пути и параметрах —
  имя сети в чужих параметрах своим не делает;
* правило живёт в питоне, а не в скрипте страницы. В скрипте его не потрогает
  ни один тест — а оно сразу же и оказалось неверным.

Проверка осталась ОДНОСТОРОННЕЙ: «сеть не обратилась к своей корзине» доказывает,
что не легло; ушедший запрос успехом не объявляется. К этому добавился разбор
ответа: код 401 называется человеку как «сеть не считает вас вошедшим», и отказ
засчитывается только когда удачных ответов не было ни одного — витрина дёргает
корзину и сама по себе.

### Счётчик корзины у Магнита не работает никогда

Кнопка шапки подписана «Перейти в корзину», текст «Корзина», числа нет ни при
пустой корзине, ни после добавления; на карточке она к тому же невидима (узел
один, видимых ноль). Страницы `/cart` у сети нет — по этому адресу отвечает
«Здесь ничего не нашлось». Ссылок про корзину в разметке нет вовсе, только
кнопка (`tools/cartcheck.py`).

Прежний `in_cart` брал число из ЛЮБОГО узла со словом «корзин» — то есть из
каждой товарной плитки, внутри которой своя кнопка «В корзину». Сквозной наряд
положил один товар, а отчёт сказал «Корзина магазина показывает 208 позиц.»:
числом оказалось количество отзывов. Отличаем по размеру узла — у настоящего
счётчика три потомка, у плитки тридцать пять и больше.

### Что осталось непроверенным

Ляжет ли позиция в корзину ВОШЕДШЕГО человека. Гостю Магнит корзину не
наполняет вовсе — обращений к ней нет ни одного, — и наряд к невошедшему не
идёт, так что работе это не мешает. Но и подтвердить успех нечем: положительного
случая под рукой нет, а значит неизвестно, каким адресом сеть зовёт корзину у
вошедшего и попадёт ли он под слова из `SENDS_CART`. Проверяется одним входом
человека в окне магазина.

Замечено попутно: на каждое нажатие Магнит дважды зовёт свой
`magnit.ru/magnit-id/anti-fraud/api/fl`. Что он решает и решает ли что-нибудь —
не выяснялось.

Инструмент замеров: `tools/pointcheck.py` (режимы `check`, `dump`, `dismiss`,
`one`, `counter`, `naryad`).

## Корзина ВкусВилла: та же стена, но видно её сразу (20.09.2026)

Вторая и последняя сеть, куда наш браузер доходит. Прогнана той же лестницей
замеров, что и Магнит, с боевого сервера.

| что мерили | Магнит | ВкусВилл |
|---|---|---|
| витрина открывается | да | да |
| проверка «я не робот» | нет | нет |
| окно, требующее выбрать магазин | **есть, только перед нашим сервером** | нет |
| кнопка «в корзину» находится | да | да |
| корзина открывается ссылкой | **нет**, только кнопкой, `/cart` → «Здесь ничего не нашлось» | **да, `/cart/`** |
| счётчик позиций в шапке | числа нет никогда | не проверялся: есть корзина целиком |
| свои запросы при нажатии гостем | ни одного | ни одного |

ГЛАВНОЕ ОТЛИЧИЕ В ПОЛЬЗУ ВКУСВИЛЛА: у него корзину МОЖНО ПРОЧИТАТЬ. Магнит
приходится проверять косвенно — по тому, обратилась ли витрина к своей корзине,
— а ВкусВилл отвечает прямо. Гостю его `/cart/` пишет:

    Главная → Корзина
    Для оформления заказа необходимо авторизоваться.

Это и есть ответ на вопрос, который висел весь день. Обе сети, куда наш браузер
доходит, корзину гостю не заводят вовсе — значит все сегодняшние «не легло»
верны и ожидаемы, а не признак поломки. Наряд к невошедшему и не идёт.

ЧЕГО НЕ СДЕЛАНО НАРОЧНО. ВкусВилл не вписан в `cart.SENDS_CART`. Хозяин его
адреса известен (`vkusvill.ru`), а вот каким ПУТЁМ он зовёт корзину — нет:
гость такого запроса не отправляет ни разу, и подставить сюда угаданные слова
значило бы завести ложное «не легло» на работающей передаче. Строка появится
после первого замера под входом человека.
