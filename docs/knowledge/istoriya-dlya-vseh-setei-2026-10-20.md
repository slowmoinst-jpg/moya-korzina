# История цен работала бы для двух сетей из одиннадцати — 20.10.2026

## Что нашлось

История цен (раунд 30) за первые сутки набрала 1 105 строк — и вся она оказалась
**у двух сетей**:

```
magnit   970 строк
metro    135 строк
```

У остальных девяти — ноль. Причина в моём коде: запись истории стояла **внутри ветки
«у сети есть точка»** (`if p.point and …`). А точка есть только у Магнита и METRO — у
остальных каталог один на страну, точки нет, и история не писалась вовсе. То есть
«обычная цена» и пометка «дороже обычного» были бы мертвы для **восьми сетей из
одиннадцати**, включая Ленту, ВкусВилл, Самокат и Пятёрочку.

Нашлось это простым замером — не кодом, а вопросом «а почему в истории только две сети?».
Никакой тест такого не поймал бы: тесты писали цены с точкой.

## Поправка

Ветка «сеть без точек» пишет историю на уровне сети (ключ — сеть и артикул, точка пустая).
Правило то же: строка только при **смене** цены (рост таблицы ограничен числом изменений),
и только если цена есть.

Тесты: история для сети без точек ведётся (новая цена сверху); двух свежих точек для суда
мало, три изменения — довод; одна и та же цена дважды не пишется. Вместе с прежними —
25 проверок по цене и истории.

## Заодно: защита цен применена на боевой базе без выкладки

Триггер `keep_seen_price` (из раунда 40) — это обычный DDL, и я применил его к живой базе
прямо сейчас, не дожидаясь конца обхода:

```
триггер в базе: ['keep_seen_price']
проба: magnit 1000303406 цена 65.99
после одиночного обнуления цена: 65.99 -> не стёрлась
вернул как было: 65.99
```

Проверил, что идущий обход не задет: за 45 секунд работы Ленты строк с ценой в базе стало
больше (100 685 → 101 372 за ~20 минут), то есть запись цен продолжается — триггер держит
только одиночное обнуление.

## Что это значит для цели

«Дороже обычного» — это про деньги, то есть прямой смысл приложения. Теперь история
пойдёт по всем сетям, а не по двум, и через неделю наблюдений (или три изменения цены)
пометка заработает сразу для всех, где цены вообще есть.
