# Стёртые цены Самоката: проверил дорогу, нашёл потерю, закрыл на уровне базы — 20.10.2026

## 1. Дверь карточек проверена целиком, по HTTP, на боевом сервере

Послал на `/api/device/cards` такую же партию, как приложение (рабочее место, секрет,
`store`, карточки с адресом, именем, ценой и наличием), и посмотрел, что стало с базой:

```
ответ двери: {got: 2, learned: 2, with_sku: 2, priced: 2, stocked: 2, repriced: 1, sku_rule: true}
строка в базе: sku=probe-…, name='Пробный товар…', price=321.5, in_stock=1, url=…
карточка с ценой 0: строка заведена, но ценой не стала
пробные строки убраны: 0
```

То есть дорога работает от HTTP до строки: заводит новый товар с ценой и наличием,
переоценивает уже известный, ноль ценой не считает. Пробные строки удалил.

## 2. Потеря: у Самоката стёрли 610 цен

Снимок проверки базы от 19.10 (1 494 строки с ценой) против сегодняшнего (884) дал
замечание — и оно оказалось настоящим, только точнее:

```
price_seen = 2026-10-19T19:51   у 1 494 строк
price IS NOT NULL               у   884 строк
→ 610 строк, где цену ВИДЕЛИ, а цены нет
```

Стёрли значения, не тронув отметку «цену видели». Это **не наш код**: обхода Самоката в
журнале нет, `upsert_products` обновляет цену через `COALESCE` (источник без цены не
стирает известную), `set_prices` пишет цену и отметку вместе. Писал другой инструмент
(в это время в дереве и в базе работала параллельная сессия).

Вернуть 610 значений неоткуда: истории цен по Самокату нет (строки пришли карточками, без
точки), `chain_prices` пуст, файлов с партией на сервере не осталось. Пока телефон не
перечитает эти карточки — цены нет, и товары выпали из сравнения (сравнимых по цене
сейчас 6 861 против 6 691 вчера, то есть остальной прирост их перекрыл).

## 3. Проверка базы теперь называет эту беду прямо

Добавил в `checkup` отдельное правило: **«цену видели, а цены нет»** — по сетям, со счётом
строк. Раньше это было видно только как «доля цен упала на 40 пунктов» (и это замечание
тоже сработало — именно оно и вывело на след). Теперь в отчёте стоит:

```
samokat: у 610 строк цену видели (price_seen), а цены нет — значения стёрты,
         товар выпал из сравнения
```

Два теста: стёртая цена = замечание; строка, у которой цены не было вовсе (Монетка) —
не замечание.

## 4. Стереть молча больше нельзя — держит триггер базы

```
CREATE TRIGGER keep_seen_price BEFORE UPDATE OF price ON chain_products
WHEN NEW.price IS NULL AND OLD.price IS NOT NULL AND NEW.price_seen IS NOT NULL
BEGIN SELECT RAISE(IGNORE); END;
```

Одиночное `UPDATE … SET price=NULL` теперь **не проходит**: строка не меняется. Законная
чистка (гасит цену и отметку вместе — так делает перенос цены Ленты) работает, обычная
запись обхода не задета. Четыре теста: одиночное стирание игнорируется, новая цена
записывается, законная чистка проходит, `upsert` не задет.
