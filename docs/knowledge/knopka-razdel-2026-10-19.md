# Кнопка «Раздел»: витрину читает телефон — 19.10.2026

Цель — разобрать товары **всех** сетей для сопоставления. Девять сетей сервер обходит
сам; Пятёрочку и Самокат витрина не пускает ни с серверного адреса, ни с домашнего
(`crawl_runs`: `blocked`, у обеих 0 строк в единой базе). Витрину видит телефон
владельца — и теперь приложение умеет отдать прочитанное серверу.

## Что сделано

**Серверная половина** (раунд 14): `app/phonecart.py: accept_cards`, дверь
`POST /api/device/cards` — до 150 карточек за заход, артикул из адреса по правилу
**этой** сети, чужие адреса и сети без правила отбрасываются, наличие пишется,
известные строки не обедняются.

**Половина приложения** (раунд 15, версия **1.14**, код 15): кнопка **«Раздел»** на
панели страницы сети. Читает карточки открытой страницы (`a[href*="/product"]`) и
отправляет их на `/api/device/cards`; в строке состояния говорит, что вышло:
«карточек 28 из 28, новых в базе 28». Отказывается работать во время сборки корзины
(«идёт сборка — раздел прочитаю после неё») и на странице без карточек («карточек на
странице нет — откройте раздел сети»).

Правила разбора карточки (`CARDS_JS`) сняты с живой витрины, а не выдуманы:

- **цена — последняя в карточке**: у товара со скидкой в тексте две цены
  («629 00 ₽ 299 99 ₽»), платит человек вторую. Первая — до скидки.
- **«629 00» — это 629 рублей 00 копеек**: пробел перед двумя последними цифрами и
  есть десятичный разделитель. Без этого правила цена уезжала в базу стократной.
- **наклейки витрины снимаются с начала названия**: «-52%», «5% на 2 кг», «Нет
  оценок», «Комбо 4,84», оценка «4,95», «от 2 шт», «Хит»/«Новинка»/«Выгодно».
  Процент внутри названия («Маскарпоне 80%») — часть товара, его не трогаем.
- **нет имени — карточку пропускаем**: имя берём из текста ссылки, иначе из `alt`
  картинки. Выдуманное имя хуже пропуска: по нему потом не сопоставить.

## Замер: дорога работает

Живой прогон на стенде, окно приложения на `https://5ka.ru/` (главная Пятёрочки):

```
до нажатия:  pyaterochka 0 строк в единой базе
нажал «Раздел»
после:       pyaterochka 28 строк
             sku 4453463  «Сосиски Папа может Сочные, 500г 500 г»      164.99
             sku 4459560  «Томаты Эко-Культура Прованс среднеплодные…»  199.99
             sku 4462402  «Чистящее средство Shima Home Strong…»        650.00
             sku 4467312  «Сыр Hochland Воппер плавленый ломтевой 40%»  129.99
```

Адрес карточки дал настоящий артикул Пятёрочки, название и цена пришли с витрины,
`in_stock` не выдуман (пусто: страница раздела наличия не говорит — наличие придёт
сборкой корзины, как и задумано). Для сравнения: серверный обход Пятёрочки в тот же
день — `blocked`, 0 строк.

Страница без карточек (несуществующий раздел) — честный отказ, в базу ничего не ушло.

## Чего эта дорога не делает

- Не заменяет сборщик: 150 карточек за заход — то, что человек прошёл глазами, а не
  каталог в десятки тысяч строк.
- Не работает с эмулятора и через домашний выход сервера — у них общий адрес
  <IP VPN владельца>, и Самокат отвечает странице «Кажется, включён VPN» (замер
  19.10.2026). Пятёрочка с того же адреса окно пускает: 28 карточек с ценами.
  Владельцу для Самоката нужен мобильный интернет.

## Прокрутка раздела (1.14.1–1.14.3)

Витрина рисует товары по мере прокрутки, поэтому одно нажатие «Раздел» читает не один
экран, а идёт вниз: собрали → прокрутили → собрали снова (пауза 1500 мс — тот же темп,
что у прочих наших шагов), пачками по 150 карточек на запрос, до 300 карточек и
14 прокруток за нажатие.

Две ошибки, найденные замером, а не догадкой:

1. **Стоп по одной пустой пробе был преждевременным.** Выдача поиска Пятёрочки
   прибавляла товары только на третьей прокрутке, через 1,6 с каждая (14 → 25).
   Приложение успевало решить, что раздел кончился, и уходило с половиной.
2. **Мало ждать — надо смотреть, докручена ли страница.** Теперь в пробе приходит не
   только список карточек, но и `scrollY` с высотой страницы: пока внизу есть место,
   идём дальше даже без новых карточек, и только у самого низа ждём две пустые пробы.

Замер после правки (окно на `https://5ka.ru/search/?text=хлеб`):

```
видно на первом экране: 12 карточек
нажал «Раздел»
строка состояния:       «Пятёрочка: карточек 24 из 24, новых в базе 24»
единая база:            pyaterochka 66 → 90 строк
```

## Итог по Пятёрочке на стенде

Четыре нажатия дали 90 строк с настоящими артикулами и ценами — там, где серверный
обход получает `blocked` и 0 строк. Строки лежат в единой базе стенда
(`data/catalog.db`): их разложит по единым товарам ближайший `match_all`.
