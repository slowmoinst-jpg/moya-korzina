# Выкладка больше не обрывает обход — 19.10.2026

## Зачем

За сутки выкладка дважды оборвала ночной обход: перезапускается контейнер
`korzina-jobs`, а вместе с ним умирает идущий обход. Следующая попытка — только по
расписанию, то есть **сутки без свежих цен** у тех сетей, до которых очередь не дошла.
19.10.2026 так вышло с Лентой: её прогон 18.10 19:07 остался последним, а сегодняшний
обход до неё не дошёл — FixPrice был убит в 07:01 и снова в 10:36.

Записи в мозге и доке об этом были, но записка не мешает второй сессии выложить правку
посреди обхода — а сессий в одном дереве несколько.

## Что сделано

1. `store.running_runs()` — идущие обходы из журнала (`status='running'`).
2. `python -m app.catalog.worker --runs` — дверь для людей и скриптов: печатает, что
   идёт, и возвращает **код 3**, если обход идёт.
3. `deploy.ps1` спрашивает сервер этой дверью и **отказывается выкладывать**, пока обход
   идёт. Выложить всё равно — `.\deploy.ps1 -Force`.

## Проверено живьём

```
$ ssh korzina 'docker exec korzina-jobs python -m app.catalog.worker --runs'
fixprice — обход идёт с 2026-10-19T10:58:29
обход идёт: выкладка оборвёт его, следующая попытка — по расписанию
код возврата: 3

$ .\deploy.ps1
Идёт обход каталога — выкладка отменена, чтобы его не оборвать:
  fixprice — обход идёт с 2026-10-19T10:58:29
Выложить всё равно — .\deploy.ps1 -Force
код возврата выкладки: 1
```

Обход после отказа продолжился (`korzina-sweep Up`, разделы FixPrice идут дальше).

**Сам сторож выложен с `-Force`** — и это правильно: обход идёт в **отдельном**
контейнере `korzina-sweep`, которого выкладка не касается (перезапускается только
`korzina-jobs`). Ради этого он и поднят отдельно.
