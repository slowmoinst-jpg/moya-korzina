# Запрос для поиска в сети: из обрубка чека — в каноническое имя — 20.10.2026

## Зачем

Живая фоновая сборка 20.10.2026 (см. `fonovaya-sborka-proverena-2026-10-20.md`) показала:
отчёты приходят, а позиции **не ложатся** — у трёх сетей из четырёх `landed=0`, и причина в
отчётах одна: «поиск сети ничего не нашёл за 12 с». В поиск уходило имя из чека:

```
Молоко neo high protein 0 5 безлактозное ультрапастеризованное 950 г
Молоко parmalat 1 8 ультрапастеризованное 1 кг
```

Это обрубки: «0 5» — жирность 0,5 %, «1 8» — 1,8 %. Сеть по такому не ищет.

## Что сделано (на сервере, не в приложении)

Порядок выбора запроса в `phonecart._query_name` стал трёхступенчатым:

1. **Привязка к единому товару** — как было: берём его полное имя.
2. **Новое: каноническое имя из единой базы по обрубку** (`_catalog_name`): ищем в каталоге
   по строкам чека (сначала целиком, потом по первым трём словам) и берём имя, только если
   сходится **фасовка в пределах 10 %** и совпадает первое смысловое слово. Не сошлось —
   имя не берём: чужой товар хуже, чем «не нашлось».
3. **Новое: чистка обрубка** (`_clean_query`): «0 5» → «0,5», «1 8» → «1,8». Склеиваем
   только очевидное — первое число 0 или 1 (жирность); «2 500 г» остаётся как есть.

## Проверено на живой базе

Логику прогнал на настоящих обрубках из отчётов владельца и на боевом каталоге:

```
было:    Молоко parmalat 1 8 ультрапастеризованное 1 кг
каталог: Молоко безлактозное ультрапастеризованное Parmalat Natura Premium Comfort 1.8% 1л

было:    Туалетная бумага papia bali flower 3 слоя 8 рулонов
каталог: Туалетная бумага Papia Bali Flower 3 слоя, 8 рулонов

было:    Сыр Galbani Маскарпоне 80% БЗМЖ 250г 250 г
каталог: Сыр Galbani Маскарпоне Дукат мягкий 80%, 250г

было:    Молоко neo high protein 0 5 безлактозное … 950 г
чистка:  Молоко neo high protein 0,5 безлактозное … 950 г
```

Три обрубка из пяти превратились в канонические имена, остальные честно чистятся.

После выкладки проверил **в бою**: наряд для телефона теперь отдаёт в поиск запрос,
собранный из канонического имени, а не из чека:

```
moloko+neo+high+protein+bezlaktoznoe+ultrapasterizovannoe+vysokobelkovoe+0+5+915ml
moloko+ultrapasterizovannoe+parmalat+pitevoe+proteinovoe+bezlaktoznoe+18+bez+zmzh+1l
```

## Мелкое, что попутно выяснилось

Скрипт выкладки ругается «приёмная дверь на порту 8765 молчит» — это ложная тревога:
дверь живёт в контейнере `korzina-jobs`, и внутри него отвечает `200 {"ok": true,
"service": "korzina-api"}`. Проверка из соседнего контейнера (`korzina`) и получает отказ,
потому что у них разные сети. Стоит поправить проверку в `server-deploy.sh`, чтобы она
смотрела изнутри нужного контейнера, — записано, не сделано.

Тесты: `tests/test_search_query.py` — шесть проверок; полный прогон 2133 passed, 2 skipped.
