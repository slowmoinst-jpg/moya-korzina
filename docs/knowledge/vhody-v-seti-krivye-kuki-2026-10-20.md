# Входы в сети не восстанавливались: кривые куки валили Chromium — 20.10.2026

## Что нашлось

На живом приложении экран «Кабинеты» (это страница сайта, открытая в окне приложения)
показал красным:

```
Не вышло: Browser.new_context: Error setting storage state:
Protocol error (Storage.setCookies): Invalid cookie fields
```

То есть **сохранённый вход в сеть не подставлялся в браузер**: Playwright отказывался
принимать состояние, и человек видел ошибку вместо своей сессии. Проверил, что лежит в
базе владельца (`shop_sessions`):

```
samokat: кук 23 | без domain 0 | sameSite не годен 23 | expires не число 23
lenta:   кук 37 | без domain 0 | sameSite не годен 37 | expires не число 37
dixy:    кук 20 | без domain 0 | sameSite не годен 20 | expires не число 20
pyaterochka: кук 13 | без domain 0 | sameSite не годен 13 | expires не число 13
пример: {'name': 'spid', 'domain': '.samokat.ru', 'path': '/', 'sameSite': None, 'expires': None}
```

Причина одна и простая: поля `sameSite` и `expires` записаны как **null**. Chromium ждёт
строку и число, а не пустоту — и валит всё состояние целиком. Задеты **все четыре
сохранённых входа** (Самокат, Лента, Дикси, Пятёрочка): входы «есть», а пользоваться ими
нельзя.

## Что сделано

`shopbrowser.store.clean_state(state)` — привести состояние к тому, что Chromium примет:

- кука без `name` или `domain` — выбрасывается;
- `expires` не число → `-1.0` (сессионная кука, а не выдуманное время);
- `sameSite` пустой или неизвестный → `Lax`; известные значения (`Strict`, `Lax`, `None`)
  сохраняются как есть;
- `path` пустой → `/`;
- localStorage чистится от записей без имени, а origin без адреса — выбрасывается.

Чистка стоит **на записи и на чтении**: сохранение всеядно (вход дороже аккуратности
формата), а браузеру всегда отдаётся уже пригодное состояние.

## Проверено на живом состоянии после выкладки

```
samokat: кук 23 | expires числами True | sameSite годен True | domain есть True
lenta:   кук 37 | expires числами True | sameSite годен True | domain есть True
dixy:    кук 20 | expires числами True | sameSite годен True | domain есть True
pyaterochka: кук 13 | expires числами True | sameSite годен True | domain есть True
   пример: {'name': 'spid', 'domain': '.samokat.ru', 'path': '/', 'sameSite': 'Lax', 'expires': -1.0}
```

Тесты: `tests/test_shop_state.py` — восемь проверок (кука без домена выбрасывается, кривые
поля приводятся к безопасным, известные `sameSite` живут, localStorage чистится, состояние
без годных кук читается как «вход есть, кук нет», сохранение не теряет то, что не почистилось).

## Урок из этой правки

Первая версия чистки **бросала ошибку**, если после неё не оставалось ни одной годной куки.
Это уронило 47 тестов: состояние с одной кукой без домена — обычное дело в проверках, и
терять из-за него вход нельзя. Правильнее: сохранение всеядно, чистит чтение. Записано в
тестах, чтобы следующая правка не сделала так же.

Вторая попытка выбрасывала куку без домена — и уронила ещё 12 тестов: система считала, что
входа нет. Оказалось, кука без домена — **не мусор, а кука этой сети**, и домен ей
подставляется по справочнику сетей (`cartrecord.CHAIN_HOSTS`). Выбрасываем только то, у
чего нет имени.

Итог: входов в сети у владельца четыре (Самокат, Лента, Дикси, Пятёрочка), и после правки
все четыре читаются в пригодном для браузера виде:

```
samokat: кук 23 | пригодны для браузера True
lenta:   кук 37 | пригодны для браузера True
dixy:    кук 20 | пригодны для браузера True
pyaterochka: кук 13 | пригодны для браузера True
```

Полный прогон: 2142 passed, 2 skipped. Выложено.

## Что удалось и что нет проверить вживую

- **Удалось:** `store.load` отдаёт пригодные куки по всем четырём входам (см. выше).
- **Удалось:** прямой вызов `live.start_live_login("magnit", phone)` больше **не падает** —
  возвращает `{ok: true, status: "starting"}`. До правки этот же путь давал ту самую
  ошибку «Storage.setCookies: Invalid cookie fields».
- **Не удалось:** подтвердить, что окно входа реально поднимается. Статус сессии в
  контейнере `korzina` остаётся `idle`: живое окно (Xvfb `:99` и браузер) живёт в
  `korzina-jobs`, и проверять его надо там. Сказать «вход восстанавливается в браузере»
  на основании этих замеров нельзя — подтверждено только, что данные для входа теперь
  годны и вызов не рушится.

## Ещё одно: плашка с ошибкой на экране — старая

Красная плашка «Не вышло: … Invalid cookie fields» на экране «Кабинеты» осталась висеть
после правки. Это **старый ответ AJAX прошлой попытки**: страница не перерисовала блок,
а журнал контейнера после выкладки (14:16 UTC) не содержит ни одной такой ошибки. Стоит
поправить: при открытии страницы старый текст ошибки не показывать (или помечать временем) —
иначе человек думает, что всё ещё сломано. Записано задачей.
