# Проверка новых строк телефонной дороги — 20.10.2026

## Что проверял

Утром в базе появились строки, которых вчера не было: **Самокат 1 512** и **Пятёрочка 682**
(было 86). Пришли дорогой карточек с телефона (`/api/device/cards`) в 19:51, прогона
обхода в журнале нет. Проверил, что в них нет мусора.

## Самокат — чисто

```
строк 1 512, с ценой 884
цена min/max: 28.00 … 4 940.00
цена < 5 ₽: 0        цена > 5 000 ₽: 0
без веса: 143        единицы: pcs 1 369, пусто 143
мусор в начале имени: 0     дублей по имени: 2
```

628 строк без цены — это карточки, на которых сеть цену не показала: честное «не знаю»,
а не ноль. Заодно проверил, что **новая цена не затирается пустой**: в `upsert_products`
обновление идёт через `price=COALESCE(?, price)`, то есть источник без цены не может
стереть цену, которую уже знаем. Это важно ровно для таких сетей, где одна дорога несёт
цену, а другая — только название и артикул.

## Пятёрочка — нашлось 25 имён с мусором

```
'Сыр Galbani Маскарпоне 80% БЗМЖ 250г 250 г 629 00 ₽'
'-22% 4,95 Томатная паста Помидорка 250мл 250 мл 205 00 ₽'
'Комбо 4,84 Суп гороховый с копченостями Пятёрочка Кафе 250г'
```

Чистильщик имён у меня есть (`phonecart._card_name`), и дорога карточек его применяет. Но
эти строки пришли **отчётом** (`/api/device/cartreport`), а в отчёте имя не чистилось —
дыра в моём коде, а не в инструменте, который их прислал.

**Поправка:** `accept_report` теперь чистит имя позиции тем же `_card_name` (чистое имя
проходит насквозь — это уже проверено отдельным тестом). Плюс тест: отчёт с текстом
карточки в имени заводит в базу чистое имя.

**И данные поправил сразу** — без выкладки, код чистки на сервере уже есть:

```
строк с мусором в имени: 25 | почищено: 25 | осталось: 0
```
