# Откуда бралась «застывшая» плашка: страницы кэшировались — 20.10.2026

## Что нашлось

Два раунда я не мог понять, почему экран «Кабинеты» в приложении показывает красную плашку
«Не вышло: … Invalid cookie fields», хотя правка сделана. Проверил журнал сервера за сутки:

```
ошибки кабинета в журнале (за сутки):  — пусто
любые упоминания cookie/state:         — пусто
```

Обработчик кабинета **логирует** исключения (`log.exception("кабинет %s: нажатие не
выполнилось")`) — если бы падало, след был бы. Следа нет. Значит страница, которую видел
телефон, пришла **не от сервера**: WebView отдал её из своего кэша.

Причина в сервере: он **вообще не ставил заголовков кэша** — ни `Cache-Control`, ни `Pragma`.
Для живых страниц (состояние входа, корзина, цены) это недопустимо: телефон показывает
прошлое, а человек думает, что всё ещё сломано. Именно это и произошло.

## Что сделано

`app/web/__init__.py` — обработчик ответа, который для **страниц** (MIME `text/html`) ставит:

```
Cache-Control: no-store, max-age=0
Pragma: no-cache
Expires: 0
```

Статику (CSS, JS, APK) не трогаем: ей кэш нужен, иначе каждая картинка едет заново.

## Проверено

Тесты `tests/test_page_cache.py`: страница отдаётся с `no-store`, статический файл — без него.
Полный прогон: 2144 passed, 2 skipped. После выкладки — на живом сервере:

```
/                     -> 200 | Cache-Control: no-store, max-age=0
/static/korzina.css   -> 200 | Cache-Control: no-cache
```

## Чему это учит

Дважды подряд я искал причину «в коде, который не работает», а она была в том, **что именно
показывают человеку**: сначала сломанная маска поиска дала ложный вывод про мёртвый код,
теперь кэш браузера дал ложную картину поломки. Правило: прежде чем чинить, убедиться, что
видишь текущее состояние, а не сохранённое. Для страниц это теперь гарантировано сервером.
