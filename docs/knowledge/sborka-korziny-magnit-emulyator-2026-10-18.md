## Честное чтение чисел

- **297,00 ₽ — это НЕ цена товаров.** `report.json` (`page_totals`) раскладывает итог:
  товары **199,00 ₽** + доставка **59,00 ₽** + сборка и упаковка **39,00 ₽** = **297,00 ₽**
  (`199 + 59 + 39 = 297`). Ответ сайта это подтверждает итогом:
  `summary.itemsTotalSalePrice=19900` (товары, копейки), `summary.totalFinalPrice=29700`
  (итог с доставкой и сборкой). Товар в корзине **один** и стоит **199,00 ₽** — колбаса.
- **`addedItemsCount=4` при `itemsCount=1`** значит: сайт принял все четыре попытки
  добавить (по одной на позицию наряда), а в корзине оказалась одна позиция. Это и даёт
  расхождение счётчиков в вердикте; «нет в наличии» у трёх подтверждено только страницей,
  не счётчиками.
- **Прогон один (n=1).** Повторов не было, выводы — про этот один прогон; сравнивать
  «до/после» на серии не с чем.

## Ревью и правки

Независимый ревьюер (Sonnet, без инструментов) вернул «не принимать» — и по делу:

- старая версия инструмента печатала «наполнилась» и `ok=true` при «1 из 4» так же, как
  при «4 из 4» — не различала полноту сборки;
- снимки не несли времени, URL, `requestId` и HTTP-статуса, поэтому доказательство не
  было привязано к прогону: старый снимок с тем же товаром сошёл бы за сегодняшний;
- в `sanitize_preview` были дыры: числа из `summary` брались по любому ключу, цены позиции
  без проверки на личные слова, обход по ключам мог принять чужой список;
- `export` копировал `report`/`plan`/логи без проверки;
- CDP глотал обрыв сокета.

Что починено:

- `tools/emucart.py` — task-8 (тесты: 60 passed): привязка снимков (время, URL,
  `requestId`, статус), строгий `sanitize_preview`, проверки `export`, честный обрыв CDP,
  вердикт с долей и `unproven`, `--allow-unbound` для старого формата;
- `tools/emu-stand.ps1` — task-9 (12 замечаний, приёмка на живой сессии), в том числе
  шаг 11 переведён с имени куки `mg_at` на `check-login` (`login=yes`);
- `check-login` — task-5: вход проверяется по словам страницы и ключам сессии
  `localStorage`, а не по устаревшей куке (`mg_at` больше не признак входа).

Что осталось непроверенным (честно):

- привязка «до»/«после» к прогону и порядок «до < отчёт < после» — снимки сделаны старой
  версией; новый инструмент так проверить их не может;
- счётчики сайта: `addedItemsCount=4` против «нажатий по легшим=1»;
- «нет в наличии» у трёх позиций — только по странице `/ecom/cart`, не по счётчикам;
- ручная «Собрать» в 1.13 не пишет в logcat (`Log.*` только в фоновой сборке,
  `MainActivity.java:2205`, `:2420`) — `logcat-korzina.txt` за прогон пуст;
- снимок страницы товара во время сборки не снят;
- прогон один (n=1).

Полное доказательство можно получить только новым прогоном на починенном стенде — тогда
снимки придут с привязкой и вердикт перестанет быть «частично». В этой задаче новый
прогон не делался: правки — только в протоколе и доказательствах.

## Как повторить

```
.venv\Scripts\python.exe -m tools.emucart plan --out plan.json
.venv\Scripts\python.exe -m tools.emucart check-login --cdp http://127.0.0.1:9222
.venv\Scripts\python.exe -m tools.emucart snap-preview --out preview-before.json
# «Собрать» — касанием кнопки панели по границам из adb shell uiautomator dump
.venv\Scripts\python.exe -m tools.emucart wait-report --since <ISO> --out report.json
.venv\Scripts\python.exe -m tools.emucart snap-preview --out preview-after.json
.venv\Scripts\python.exe -m tools.emucart verdict --plan plan.json ^
    --before preview-before.json --after preview-after.json --report report.json --out verdict.json
.venv\Scripts\python.exe -m tools.emucart export --run <каталог прогона> --to <этот каталог> --logs
```

Снимки, снятые старым инструментом, вердикт без `--allow-unbound` не принимает («не
доказано», exit 30) — это правильное поведение. Новый прогон на починенном стенде снимет
снимки с привязкой, и `--allow-unbound` не понадобится.

Порт отладки `9222` перебрасывается заново после каждого перезапуска приложения: pid
в `adb shell cat /proc/net/unix | grep webview_devtools_remote` меняется (в прогоне — 16463).

Боевой сервер и данные владельца не трогались: `deploy.ps1` не запускался, `ssh korzina`
не вызывался, том `korzina-data` не затрагивался. В Магните только наполняли корзину:
«Оформить», «Оплатить», «Удалить», «Очистить корзину» не нажимались, окнам сайта «да»
не отвечали.
