# Дорога к Пятёрочке и Самокату: ищет и находит телефон человека

Продолжение проверки единой базы 18.10.2026 (первая часть — [proverka-edinoi-bazy-2026-10-18.md](proverka-edinoi-bazy-2026-10-18.md),
полнота Ленты — [polnota-lenty-2026-10-18.md](polnota-lenty-2026-10-18.md)).

## Зачем

Пятёрочка и Самокат — две сети, которых в единой базе нет ни строки. Проверено живьём
18.10.2026: сервер им не нужен ни с одного нашего адреса.

| Что пробовали | Ответ сети |
|---|---|
| витрина 5ka.ru напрямую с сервера (`<сервер>`, Timeweb) | «Проблемы со связью. Проверьте настройки интернета и VPN … IP: <сервер>» |
| витрина 5ka.ru через домашний выход владельца (`<IP домашнего выхода>`, P.A.K.T, СПб, домашний) | 200 и та же фраза, только IP домашний — **0 товаров** |
| Chromium с исполнением JS, и headless, и с окном на Xvfb | то же: страница защиты, товаров 0 |
| карта сайта 5ka (`sitemap_5ka.xml` — адрес из robots.txt) | та же заглушка 1,8 КБ вместо XML |
| API Самоката (`api.samokat.ru/api/v1/categories`, `/products`, …) | 200 со всё той же заглушкой ServicePipe (1,8 КБ, не JSON) |
| robots.txt обеих сетей | открыт — и только он |

То есть серверная дорога закрыта принципиально, и «достать каталог» можно только там, где
человек — обычный покупатель: **в приложении на его телефоне**, с его входом и мобильным
адресом. Приложение уже умеет открывать сеть у себя и нажимать кнопки (версия 1.13 собирает
там корзину в фоне). Теперь оно умеет и приносить оттуда товар.

## Что сделано (закончено, ждёт первого живого захода)

**Сервер** (всё покрыто тестами, `tests/test_phone_learns_skus.py`, 17 тестов):

1. **Наряд отдаёт телефону список «найди сам»** — `phonecart.plan` → поле `search`:
   `[{product_id, name, url}]`, где `url` — адрес поиска этой сети из `config.yaml`
   (`search_url.<сеть>`, проверен живыми запросами 15.09.2026). В список попадают только
   те позиции корзины, которых сеть не знает после всех серверных попыток (каталог +
   живой поиск), и не больше `SEARCH_LIMIT = 8` за наряд: поиск — это запрос к сети на
   каждую позицию.
2. **Отчёт телефона учит единую базу** — `phonecart.accept_report` теперь хранит адрес
   карточки у каждой легшей позиции, а `phonecart._learn` достаёт из него **настоящий
   артикул сети** (`app/catalog/fromurl.py`) и заводит товар в общую базу
   (`refresh.learn_device_rows`). Адрес проверяется по списку хостов сети
   (`cartrecord.CHAIN_HOSTS`): чужой адрес в базу не пускается. Заглушки (`hist-`,
   `list-`, `preview-`, `<сеть>-…`) не пишутся, известные строки не переписываются (у
   сборщика название и цена полнее), за один отчёт — не больше 20 строк.
3. **Артикул из адреса — по правилу самой сети** (`app/catalog/fromurl.py`): у Пятёрочки и
   Самоката правило сверено с их сборщиками (`sku_from_url`), у Магнита, Ленты, Дикси,
   Монетки и Fix Price — по виду адреса карточки из живых замеров 16–20.09.2026. Не узнали
   артикул — товар не записываем: лучше пропустить строку, чем положить в базу чужой номер.

**Приложение** (Android, собрано и опубликовано):

4. **`search` в наряде — новый шаг сборки**: строка с пометкой `search` сначала открывает
   страницу поиска сети, берёт первую карточку товара, **сверяет её название с названием
   позиции** (общее слово от четырёх букв — иначе в корзину человека лёг бы не тот товар),
   и только потом идёт обычным путём: касание «В корзину», проверка, отчёт. Адрес найденной
   карточки уходит в отчёте — и сервер заводит товар в единой базе. Со следующего наряда эта
   сеть знает товар, и искать его уже не надо.
5. **Отчёт о сборке теперь несёт адрес карточки** каждой легшей позиции.

Сборка APK: `BUILD SUCCESSFUL`, файл обновлён на сервере —
`http://<сервер>/static/moya-korzina.apk` (`app/web/static/moya-korzina.apk`).

  (телефон, каталог, Лента, честность обхода).
- APK: `docker run … -e KORZINA_SERVER=http://<сервер> … korzina-apk` →
  `BUILD SUCCESSFUL`; в опубликованном APK проверены строки: адрес сервера,
  `firstCard`, «поиск сети ничего не нашёл», «поиск сети нашёл не тот товар».
- Живая проверка на боевом сервере (после выкладки): наряд отдаёт телефоно-поиск
  для Пятёрочки и Самоката (и ничего для METRO, у которой адреса поиска нет);
  артикулы из адресов берутся (78001656 у обеих сетей, 1000227406 у Магнита),
  чужой адрес — `None`; известный артикул Магнита не переписывается (`learn=0`),
  заглушка `hist-42` не пишется (`0`).
- Дымовая проверка приложения на эмуляторе: стенд (`tools/emu-stand.ps1 -Until 10`)
  поднял эмулятор, собрал и поставил APK с этими правками (`versionName 1.13`,
  `lastUpdateTime 19:59 UTC`), приложение запустилось и **ни разу не упало** — в
  `logcat -b crash` пусто, процесс живой, экран снят. Приложение при этом ходило на
  местный сервер (журнал 8611: наряд Магнита в 23:00:47 — «незнакомых 12, в каталоге 1»).
  **Чего дымовая проверка не показала:** сам шаг поиска; местный сервер был поднят до
  правок и поля `search` в наряде не отдавал, а сети на адресе эмулятора закрыты — шаг
  ждёт первого живого захода владельца с телефона.

## Два дефекта, найденных по дороге

1. **Кнопка «Скачать APK» раздавала сборку без адреса сервера.** `tools/build_apk.ps1`
   не передавал `KORZINA_SERVER`/`-PkorzinaServer`, а `build.gradle` берёт адрес только
   оттуда: в APK уезжала пустая строка, и приложение показало бы «Адрес сервера не задан
   при сборке». Теперь скрипт берёт боевой хост из ssh-псевдонима и передаёт его в сборку.
2. **Свежая сборка не доезжала до кнопки.** Скрипт клал APK только в
   `app/web/static/moya-korzina.apk` (образ, пропадает при перевыкладке), а
   `app/web/apk.py` раздаёт `data/apk/moya-korzina.apk` из тома. Замер: собрано
   66 921 байт, раздавалось 21 025 (старая сборка). Теперь скрипт кладёт APK в том,
   и проверено совпадением sha256: локальный файл = то, что отдаёт сервер.

## Чего это НЕ даёт и что осталось

- **Живого захода в Пятёрочку/Самокат в этой проверке не было**: эмулятор и хост сидят на
  адресе, который эти сети не пускают. Нужен телефон владельца с мобильным интернетом:
  после первого захода в сеть из приложения в базе появятся его товары, а следующий наряд
  будет их знать. Это проверяется по `crawl_runs`-подобному следу: строки сети в
  `chain_products` с `first_seen` после захода и `link_method`/`method` от телефона.
- **Корзина для этих сетей по-прежнему собирается только из того, что человек положил**,
  но теперь каждая положенная позиция запоминается: второй раз её не искать.
- Опыт показывает: пока сеть не пускает сервер, полноту её каталога определяет, сколько
  человек ею пользуется. Это честная цена закрытого источника, а не недоделка.
