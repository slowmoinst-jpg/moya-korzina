# Сбор Самоката и Пятёрочки настоящим браузером через туннель — 19–20.10.2026

Зачем. Серверный Playwright получает у обеих сетей заглушку ServicePipe (замеры
18–19.10.2026): в единой базе Самокат был пуст (0 строк), Пятёрочка — 86 строк от
18.10. Владелец 19.10.2026 указал: доступ к сайтам — через туннель ноутбука,
Playwright-Chromium («chrome for dev») не использовать — он в этих сетях не проходит.

## Как собирали

1. **Туннель.** С рабочей машины SSH-форвард на серверный SOCKS домашнего выхода:
   `ssh -N -L 1081:127.0.0.1:1080 korzina`; выход = домашний адрес владельца
   <IP домашнего выхода> (P.A.K.T, СПб). Через него же ходит серверный обход.
2. **Браузер.** Установленный Google Chrome (не Playwright), запущен отдельным
   процессом: `--proxy-server=socks5://127.0.0.1:1081 --remote-debugging-port=9335`,
   обычное окно. Playwright подключается к нему по CDP (`connect_over_cdp`) — свой
   Chromium не запускается.
3. **Страницы.** Самокат — `https://samokat.ru/search?value=<запрос>` (страница поиска
   отдаёт ~126 карточек и не просит адрес). Пятёрочка — главная (30 карточек) и
   `https://5ka.ru/search/?text=<запрос>` (~12 карточек); страницы категорий 5ka без
   выбранного адреса доставки пусты.
4. **Разбор карточки.** Самокат — по разметке: имя из `title` блока
   `ProductCard_name` (полное, с фасовкой), цена из блока действий БЕЗ узла
   `oldPrice` и без `<s>/<del>` — старая и новая цена стоят соседними узлами и в
   `innerText` склеиваются («186165 ₽» = старая 186 и новая 165). Пятёрочка — из
   подписи карточки: имя до ПЕРВОЙ цены, платим за ПОСЛЕДНЮЮ; снимаются наклейки
   витрины («Классная цена», «Комбо», «-52%», «Нет оценок», «от 2 шт»,
   «1 2 … Больше нет», хвост «·Снизили цену»).
5. **Заливка.** Та же дверь, что у телефона: `phonecart.accept_cards({"store": …,
   "cards": […]})` внутри контейнера, по 150 карточек (CARDS_LIMIT), артикул из адреса
   через `fromurl.sku_of`. Серверный скрипт кладётся в `/tmp` и запускается с
   `-e PYTHONPATH=/app` — иначе `app` из скрипта не импортируется.
6. **Сопоставление.** `python -m app.catalog.worker --match` в ОТДЕЛЬНОМ контейнере
   (`docker run -d --name korzina-match -v korzina-data:/app/data korzina:latest …`):
   выкладка параллельной сессии убивает exec-процесс в korzina-jobs (exit 137),
   отдельный контейнер её переживает.

| Пятёрочка, строк | 86 | **682** (+596 новых) |

Первый заход дал 1512 строк Самоката и 596 новых строк Пятёрочки; повторный сбор по
тем же страницам (после исправления разбора цен) — ещё **107 новых артикулов** и
цены для 1591 строки: 884 правдоподобные цены первого захода заменены полными,
«пустых» осталось 28 (у них цена не разобралась и в разметке).

Сквозное сопоставление: среди всех строк Самоката **466** попали в единые товары,
известные двум и более сетям (Пятёрочка — 305 из первого захода). Примеры: молоко
Простоквашино, Домик в деревне, Parmalat; шоколад Alpen Gold; вода Borjomi; из
второго захода — творожный сыр Экомилк, йогурт Растишка, сок «Сады Придонья»,
фрикадельки «Ближние Горки» — сошлись с 4–7 сетями.

Привязка чеков владельца (`link --all --dry-run`, замер 20.10 утром, во время ночного
обхода): было 348 из 1159 → стало **387**; по чекам наших сетей 187 (39,0 %) → **219
(45,7 %)**; не найдено 273 → 242. Часть прироста дали и ночные обходы — сравнивать
надо с базовой линией 19.10 утра (`bazovye-chisla-2026-10-19.json`).

## Грабли

- **Цены Самоката (найдено и исправлено 20.10.2026).** В разметке карточки старая
  цена лежит отдельным узлом `ProductCardActions_oldPrice`, а новая — соседним
  текстом; `innerText` склеивает их без пробела: «186165 ₽» — это старая 186 и новая
  165 ₽. Первые версии сбора читали именно `innerText` и получали мусор (610
  значений обнулены). Правильный разбор — по DOM: имя из `title` блока
  `ProductCard_name`, цена из блока действий без `oldPrice`/`<s>`/`<del>`. После
  исправления у 1591 строки Самоката настоящие цены (диапазон 19–21 240 ₽, дорогие —
  парфюмерия), 28 цен не разобрались.
- **ServicePipe.** После ~16 страниц подряд Самокат отдаёт проверку `/xpvnsulc/` и
  перестаёт пускать профиль. Проверка проходящая: свежий профиль Chrome проходит её
  сам, а старый остаётся заблокированным; поэтому сбор идёт порциями по 6 страниц с
  паузами 45 с, а увидев проверку — инструмент ждёт, один раз перезагружает и, если
  не отпустило, останавливается.
- **Полнота.** Поиск Пятёрочки отдаёт ~12 карточек на страницу — полный каталог без
  выбора адреса доставки недоступен. Самокат отдаёт ~126 на страницу поиска.
- **`docker exec`.** Python-скрипт из `/tmp` видит пакет `app` только с
  `PYTHONPATH=/app`; `docker exec … sh -c "cd /app && python /tmp/…"` не помогает —
  sys.path[0] равен каталогу скрипта.

## Повторяемый инструмент

`tools/browser_cards.py` — сбор карточек. Playwright подключается по CDP к уже
запущенному Chrome (свой браузер не поднимает), идёт порциями, пережидает проверку
ServicePipe и останавливается, сохранив собранное:

```powershell
python tools/browser_cards.py --chain samokat
python tools/browser_cards.py --chain both --portion 6 --pause 45
python tools/browser_cards.py --chain samokat --queries "молоко,хлеб,сыр"
```

Перед запуском — туннель и Chrome по шагам 1–2; результат в
`data/browser_cards/cards_<сеть>.json`.

`tools/browser_cards_ingest.py` — заливка в боевую единую базу той же дверью, что у
телефона (`phonecart.accept_cards`). Повторный сбор по тем же страницам обновляет
цены, а не плодит дубли:

```powershell
python tools/browser_cards_ingest.py data/browser_cards/cards_samokat.json
python tools/browser_cards_ingest.py data/browser_cards --match
```

`--match` запускает сопоставление в отдельном контейнере (`browser-match`), которое
выкладка не перезапускает; журнал — `docker exec browser-match tail -5 /tmp/match.log`.
