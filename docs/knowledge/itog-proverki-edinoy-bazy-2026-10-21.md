## 2. База формируется на постоянной основе

- **Плановый обход** — каждый день в 03:30 UTC (`catalog.refresh_at`), свежие сети
  пропускаются (`fresh_hours: 12`). Замер 21.10: шесть сетей, 03:30 → 04:15, **45 минут**
  (было 8 часов, пока сети шли по очереди).
- **Живая дорога днём** — дозор цен каждые 15 минут (`pricewatch`), приносит свежие цены
  по корзине; проверено вживую: проход «устарело 16, свежих цен записано 14» по пяти сетям,
  всё легло в базу человека (`data/users/<номер>/basket.db`), общая база осталась пустой.
- **Телефон** — «Раздел» читает карточки в любой момент (`/api/device/cards`), проверено:
  `magnit: cards, got 31`.
- **Пометка обхода** снимается в `finally`, шаг пишется по каждой сети, проверка базы
  ругается, если обход помечен идущим больше 3,5 ч.

## 4. Наличие и цены из фоновой сборки корзины

Механизм целый, проверен сквозняком: приложение открывает сеть в своём режиме →
«Собрать» собирает корзину в фоне → отчёт (`/api/device/cartreport`) → позиция ложится
в корзину человека и в историю. Экран корзины показывает правду по каждой сети
(«легло 1 из 4», «не вышло», причина в позиции).

Что мешает массово: **стена по IP** — витрины Магнита, Дикси, Пятёрочки, Самоката
отвечают серверу и эмулятору проверкой («выключите VPN», «if you are not a bot»).
Работает только телефон владельца на мобильном интернете. Это шаг человека, а не дефект.

Появился `app/storefind.py` — **серверный поиск вместо поиска телефоном в витрине**:
`find(store, name, pack_g, lat, lon)`, `find_chains(...)` (по нескольким сетям разом) и

запросом, кэш на сутки с версией формы ответа, паузы 1,5/1,0/2,0 с.
Ответ честный: `ok=True` только при уверенности ≥0,75 и отсутствии различий; иначе —
«нет товара в сети» / «у сети похожее под другим названием» / «другая линейка или фасовка:
чем именно» / «сервер не смог». Кладём только `ok=True`.

**Лимит шлюза Магнита (найдено 21.10):** `term` длиннее ~66 символов → **400 Bad Request**
(64 → 200, 67 → 400). Канонические имена с запятыми и процентом не проходили, и поиск
честно писал «сеть ничего не нашла», хотя шлюз отвергал запрос. Теперь `_clamp_term` режет
до 64 знаков по границе слова.

## Известное ограничение: имена sitemap-сетей транслитерированы

Замер 21.10.2026: русское имя есть у 37,4 % единых товаров (108 660 из 290 801), у 182 141
имени кириллицы нет. Причина — три sitemap-сети: у Перекрёстка 159 222 строки из 159 222
латиницей, у Vprok 27 551 из 27 551, у Монетки 7 785 из 7 785 (плюс 750 строк Дикси). Это
не марки, а транслитерация слагов их перечня («tomaty cerri medovye na vetke…»). У Ленты,
METRO, ВкусВилла, FixPrice, Магнита, Самоката и Пятёрочки латиницы нет вовсе.

Склейка от этого не страдает (свод письма в сопоставлении терпит кириллицу и латиницу),
но имя товара — это ещё и запрос в русскую витрину. Правило выбора имени теперь берёт
русское написание, если оно есть у товара; для товара, собранного ТОЛЬКО из sitemap-сетей,
русского имени нет, и телефон искал бы латиницей. Запасной путь (в _query_name): если имя
из единой базы без кириллицы, а имя из чека русское — искать по имени чека.

## Обучение базы цене с НЕУДАЧНЫХ кладок (21.10, вечер)

**Зачем.** Пятёрочку и Самокат сервер не обходит вовсе, Дикси обходит частично. Если товар
не лёг в корзину, раньше мы не узнавали ничего. Теперь телефон присылает цену и адрес
карточки, которую человек ВИДЕЛ, и цена уходит строке СЕТИ — по артикулу из адреса.

**Как сделано:**
- `refresh.note_device_prices` — второй проход: позиция `ok=false`, но есть `price>0` и
  `url` → `fromurl.sku_of(chain, url)` → цена и наличие пишутся строке сети с этим
  артикулом. Нашему товару — никогда: телефон мог открыть карточку другой линейки
  («Papia Тропическая экзотика» вместо нашей «Bali Flower»).
- `store.set_prices_seen` / `set_stock_seen` — пишут цену/наличие, ставят `price_seen` и
  **оживляют строку** (`active=1`, `last_seen`): `active=0` значит «обход не увидел», а не
  «товара нет», и человек, открывший карточку, доказал его жизнь.
- `store.touch_seen` — отдельно для известных строк: телефон видел карточку → `last_seen`
  и `active=1`, но имя/цена/штрихкод обхода не переписываются. Звать только при
  доказанном наблюдении (`price>0`), иначе «страница не отдалась» выдаётся за визит.
- `fromurl` понимает адреса Дикси вида `/catalog/<раздел>/<подраздел>/<sku>/` — именно их
  отдаёт наш серверный поиск; без этого правило теряло строки Дикси целиком.

**Подделка свежести (найдено и закрыто).** Частичный обход добирает известные товары из
нашей же базы и ставил им `price_seen=now` — 153 строки Пятёрочки и Самоката попали в
6-часовое окно доверия, хотя сеть их не подтверждала. Теперь у `ChainProduct` есть флаг
`price_from_base` (поле объекта, не колонка базы), и метка ставится только за цену, которую
назвала сеть. Ложные метки репетиции сняты, цены сохранены.

**Проверено на боевом (прогон 10:10 UTC):**
```
magnit 8000104060  price=119.99  active=1  price_seen=2026-10-21T10:40:11
magnit 1000193728  price=349.99  active=1  price_seen=2026-10-21T10:50:27
devicecheck: ЦЕН ОБНОВЛЕНО за 6 ч: 2   ← было 155, из них 153 были ложными
```
То есть цикл замкнут: карточка → артикул → строка сети → цена/наличие → сопоставление,
и это работает даже когда кладка не удалась.

**Команды проверки:**
```
docker exec -i -w /app korzina-jobs python -m app.catalog.devicecheck --hours 6
docker exec -i -w /app korzina-jobs python -m app.humansteps --phone <телефон>
```
`devicecheck` показывает и новые строки, и обновлённые цены; порядок — по свежести, и в
подписи честно сказано, что источник у метки — сеть ИЛИ телефон.
