# Бюджет добора покупает сравнения, а не случайные строки — 19.10.2026

## Что измерено

Единая база существует ради сравнения сетей. Вот сколько этого сравнения есть на самом
деле (замер 19.10.2026, 12:50 UTC):

```
строк с ценой ............................. 95 346
единых товаров, у которых >=2 сети ......... 12 788
... и хотя бы у двух сетей есть цена ....... 6 398   ← их можно сравнить по цене
... из них ещё и с наличием ................ 5 800
товаров, у которых есть сеть без цены ...... 196 481  ← ждут цены
```

Распределение: по одной сети с ценой — 77 929 товаров, по две — 4 689, по три — 1 232,
по четыре — 373, по пять — 96, по шесть — 8. То есть сравнение пока есть у 6 398
товаров из 275 тысяч — и почти всё упирается в три сети без цен вовсе (Перекрёсток
158 698 строк, Vprok 27 551, Монетка 7 772) и в невыбранные цены у остальных.

## Что поправлено

Добор подробностей у Ленты тратит **6 000 карточек за ночь**. Очередь (`store.thin_skus`)
шла «от старых к новым» — то есть бюджет уходил на что попало: в ночь 19.10 из
спрошенных карточек половина оказалась мёртвыми артикулами sitemap, а сколько из живых
дало сравнение — никто не считал.

Теперь очередь такая: **сначала строки, у которых родня уже с ценой** (цена такой строки
сразу даёт сравнение сетей), потом строки с роднёй вовсе, потом остальные; внутри группы
— от старых к новым.

Плюс вторая дыра: в очередь не попадала строка **без цены, но с маркой и штрихкодом** —
а карточка сети отдаёт и цену. У Ленты таких нашлось 813. Теперь цена входит в условие
добора наравне с маркой и штрихкодом.

## Проверено на живой очереди

```
очередь добора Ленты: 6000 строк
в первой тысяче: с роднёй С ЦЕНОЙ — 1000, с роднёй вообще — 1000
первые артикулы: 393, 2335, 2791, 2920, 3289
```

То есть каждая из первой тысячи карточек, которую добор возьмёт следующей ночью, сразу
даст сравнение сетей по цене. Прежний порядок был слеп: он начинал с самых старых строк
и о родне не знал ничего.

Тесты: `tests/test_thin_skus_order.py` — четыре проверки (приоритет по родне с ценой,
строка без цены в очереди, полная строка не в очереди, предел соблюдается); обновлён
`tests/test_lenta_brand_barcode.py` под новое правило. Полный прогон: 1905 passed,
2 skipped.

## Что это меняет для цели

«Парсинг всех товаров с целью сопоставления» — теперь бюджет ночи работает на
сопоставление, а не на инвентаризацию. И видно, куда двигаться дальше: 196 481 товар
ждут цены, из них основная масса — три сети, у которых цен нет вовсе; для них цена
приходит только корзиной владельца (серверная и приложенческая половины этой дороги
готовы, проверена сквозным прогоном).
