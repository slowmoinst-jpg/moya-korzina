# Поправка: экран у веб-процесса ЕСТЬ, а живые сессии — в его памяти — 20.10.2026

## Что я сказал вчера и почему это было неверно

В раунде 58 я записал: «живое окно входа в проде недоступно — ни в web-, ни в jobs-контейнере
нет DISPLAY, `live.is_live_available()` отвечает False». **Это был артефакт замера.**
Проверял я через `docker exec`, а `docker exec` не наследует переменные окружения точки
входа. А `tools/entrypoint.sh` делает ровно то, что нужно:

```sh
if start_screen; then
    DISPLAY=":${SCREEN_NUM}"      # Xvfb :99, 1280x1024x24
    export DISPLAY
fi
echo "вход: запускаю $*"
exec "$@"                          # python -m app.web.server
```

То есть у **основного** процесса веб-сервера экран есть, и окно входа доступно. Мой
`docker exec … python -c …` создавал второй процесс без `DISPLAY` — и я сделал вывод про
всё приложение по нему.

## Вторая поправка: живые сессии живут в памяти процесса

`live.py` держит сессии в словаре процесса и поднимает поток. Значит:

- запуск `live.start_live_login` через `docker exec` создаёт сессию в **одноразовом**
  процессе, который тут же умирает, — отсюда «статус `idle`», который я увидел;
- спрашивать статус надо у **того же** процесса, что начал, то есть только через HTTP.

## Что осталось непроверенным — честно

Сквозную проверку живого окна через HTTP сделать не удалось: `POST /cabinet/act?store=magnit`
(endpoint `screen.cabinet_act`, требует `auth.needs_phone`) отвечает HTML-страницей вместо
JSON — мой вход по номеру (`POST /` с телефоном) не дал веб-сессии. Нужен настоящий клиент
с кукой, то есть живой браузер/страница.

Итог: **данные для входа починены** (`store.load` отдаёт пригодные куки по всем четырём
входам, вызов `live.start_live_login` больше не падает), а **само окно вживую не проверено**
— это осталось открытым пунктом.

## Урок

Два раза подряд я сделал вывод по замеру, который мерил не то: сначала «мёртвый код» по
сломанной маске поиска, теперь «нет дисплея» по `docker exec`. Правило на будущее: если
проверяю окружение процесса — проверять **изнутри того же процесса** (через его HTTP-ручку
или лог), а не из соседней оболочки.
