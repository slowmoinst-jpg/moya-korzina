# Брошенные обходы больше не врут — 19.10.2026

## Что нашлось

Разбираясь, почему после выкладки обход «завис», обнаружилось: строк со статусом
`running` в журнале накопилось **15**, и самые старые — от **16.09.2026**:

```
metro     2026-09-27T14:06 → висела до 19.10
metro     2026-09-27T13:37
metro     2026-09-27T13:15
vkusvill  2026-09-19T09:22
lenta     2026-09-17T09:07
magnit    2026-09-17T08:53
vkusvill  2026-09-16T15:26
```

Причина понятна: планировщик живёт в контейнере, который перезапускается при каждой
выкладке, а каждое прерывание посреди обхода оставляло строку «идёт» навсегда. По таким
строкам нельзя понять, обошлась сеть или нет, — а на экране сетей «идёт обход» висело
неделями.

## Что сделано

`store.close_stale_runs(hours=6)` — закрывает брошенные обходы (`running` старше порога →
`failed` с честной причиной), и `worker.serve()` зовёт её при запуске, рядом с
`revive_stuck()` (тот же приём для очереди адресов).

**Почему порог по времени, а не «всё, что running».** Обход бывает живым и в другом
контейнере: 19.10.2026 ночной обход после выкладки возобновляли отдельным контейнером
`korzina-sweep`, и служба не должна объявлять чужой живой обход провалившимся только
потому, что сама перезапустилась. Потолок времени на сеть — 180 минут, шесть часов выше
любого живого обхода.

Проверено в живом контейнере после выкладки:

```
close_stale_runs: True | порог по умолчанию: (hours: float = 6.0) -> int
вызывается при запуске службы: True
строк running сейчас: 1        ← это живой обход fixprice в korzina-sweep, его не тронули
```

Тесты: `tests/test_stale_runs.py` — три проверки (брошенный закрывается, живой чужой не
трогается, завершённый не трогается). Полный прогон: 1885 passed, 2 skipped.

## Заодно: урок про выкладку

Дважды за сутки выкладка (моя и параллельной сессии) убивала идущий обход: контейнер
`korzina-jobs` перезапускается, обход обрывается, а следующий назначен на 20.10 03:30 —
то есть сутки без обхода у тех сетей, до которых очередь не дошла. Возобновлять
приходится вручную по очереди сетей, и лучше это делать **отдельным контейнером**
(`docker run -d --name korzina-sweep -v korzina-data:/app/data korzina:latest …`): его
выкладка не трогает. Так и сделано — обход идёт с 10:58 UTC.
