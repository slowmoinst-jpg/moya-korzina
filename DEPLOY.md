# Развёртывание

## Почему не Vercel

Vercel исполняет serverless-функции: запрос пришёл — функция отработала — процесс умер.
Streamlit устроен иначе: это долгоживущий сервер на Tornado, который держит WebSocket-соединение
с каждой вкладкой и хранит состояние сессии в памяти процесса. Положить его на Vercel нельзя —
ни через `@vercel/python`, ни через адаптер: соединение рвётся, состояние теряется.

К этому добавляются два свойства нашего приложения:

- **Файловая база.** SQLite пишет в `data/basket.db`. У serverless файловая система эфемерная и
  доступна только на чтение вне `/tmp`, так что история покупок и сопоставления не переживут запрос.
- **Кэш цен** (`data/cache/`) рассчитан на то, что процесс живёт дольше одного запроса.

Поэтому нужен контейнерный хостинг или площадка самого Streamlit.

## Варианты, которые подходят

| Площадка | Чем платим | Как |
|---|---|---|
| **Streamlit Community Cloud** | бесплатно, нужен публичный или приватный репозиторий GitHub | Подключить репозиторий, ветка `main`, главный файл `streamlit_app.py`. Диск эфемерный — база обнуляется при перезапуске |
| **Render** | бесплатный тариф засыпает, диск от 7 $/мес | Web Service из `Dockerfile`, том смонтировать в `/app/data` |
| **Railway** | по потреблению | Deploy from Dockerfile, том в `/app/data` |
| **Fly.io** | по потреблению | `fly launch` подхватит `Dockerfile`, том `fly volumes create` в `/app/data` |
| **Свой VPS** | своя машина | `docker build -t korzina . && docker run -p 8501:8501 -v korzina-data:/app/data korzina` |

Образ уже собран под все эти площадки: [Dockerfile](Dockerfile) читает порт из `PORT` и слушает
`0.0.0.0`. Том надо монтировать именно в `/app/data` — иначе при каждом передеплое пропадут база,
сопоставления и история цен.

## Что обязательно сделать до публичного адреса

1. **Понимать, что видно снаружи.** Авторизации в MVP нет сознательно (раздел 3.2 спецификации:
   «без авторизации, один пользователь»). В репозитории лежат только демонстрационные данные —
   вымышленный чек и вымышленные условия карт, — поэтому публичный репозиторий безопасен.
   Но как только вы загрузите в приложение собственный чек или впишете настоящие условия карт,
   они станут видны любому, кто знает адрес приложения. Тогда нужен пароль через `st.secrets`,
   режим Private app в настройках Community Cloud или закрытая сеть.
2. **Решить, где живут данные.** Либо том, примонтированный в `/app/data`, либо переход на
   PostgreSQL (он и так в дорожной карте, раздел 10, пункт 5).
3. **Проверить коннекторы с чужого IP.** Магнит и ВкусВилл отвечают 404 и таймаутом уже локально;
   с хостингового IP поведение может отличаться, и расчёт пойдёт по `data/fallback_prices.csv` —
   это демонстрационные цены, а не настоящие.

## Локальный запуск в контейнере

```bash
docker build -t korzina .
docker run --rm -p 8501:8501 -v korzina-data:/app/data korzina
```

Первый запуск создаёт пустую базу. Демо-данные наливаются командой:

```bash
docker run --rm -v korzina-data:/app/data korzina python tools/seed.py
```
